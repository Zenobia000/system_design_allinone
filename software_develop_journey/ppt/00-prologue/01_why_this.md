## WHY · 開發者誤解

<span class="kicker">SECTION · MISCONCEPTION</span>

# AI 寫得出 code，為什麼還要這麼多角色？

<br>

<div class="highlight">

很多人被 Cursor / Copilot / Claude Code 影響，以為：
**「以後一個人 + AI 就能搞定整個產品」**。

這是錯的——AI 解決了「實作」，沒解決「**判斷該實作什麼**」。

</div>

<br>

- AI 把 coding 變成 commodity
- 真正稀缺的變成「定義問題」「拆解系統」「控制複雜度」
- 這正是 9 個角色各自在做的事

## WHY · 不確定性階梯

# 每個角色降低一種不確定性

<!-- _class: compact -->

| 角色 | 降低的不確定性 |
|---|---|
| PM | 商業價值不確定性 |
| UX | 使用者行為不確定性 |
| SA | 業務規則不確定性 |
| Architect | 系統演進與非功能風險 |
| SD | 開發落地不確定性 |
| DBA | 資料正確性、效能、可靠性風險 |
| Dev | 實作正確性不確定性 |
| QA | 結果正確性不確定性 |
| DevOps / SRE | 上線運行不確定性 |

<br>

<span class="muted">**核心金句**：角色不是用職稱分，而是用它負責消除哪一種不確定性來分。</span>

> Source: _source/braindump.md · §角色 = 消除不確定性

## WHY · 你會帶走什麼

<span class="kicker">DELIVERABLE</span>

# 讀完你能回答這 3 題

<div class="tradeoff">
  <div class="pro">
    <h3>知道是什麼</h3>
    <ul>
      <li>每個角色一句話定義</li>
      <li>蓋大樓對應的具體角色</li>
      <li>每天時間花在哪</li>
      <li>3-5 個經典產出</li>
      <li>看得懂招聘 JD</li>
    </ul>
  </div>
  <div class="con">
    <h3>知道邊界在哪</h3>
    <ul>
      <li>SA 跟 PM 差在哪</li>
      <li>SD 跟 Architect 差在哪</li>
      <li>誰主導什麼決策</li>
      <li>哪些會 overlap</li>
      <li>哪些會打架</li>
    </ul>
  </div>
</div>

<span class="muted">**最重要的第 3 題**：知道自己想做哪個角色，去哪裡深挖。</span>
