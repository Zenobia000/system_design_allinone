# 定義「對」—AI 時代尤其難

<br>

**經典產出**：測試計畫、test case、自動化 script、bug report、回歸驗收。

**判斷力核心**：
- AI 系統的「對」要怎麼定（沒有 ground truth）？
- 哪些 case 是 must test、哪些是 nice？
- 上線後監控誰能取代手動測試？

## QA · AI 協作模式

<div class="prompt">

**典型 prompt**：

```
功能規格：[貼 spec]
請列出 30 個測試案例，分為：
- Happy path (5)
- 邊界值 (10)
- 異常輸入 (10)
- 並發 / 競態 (5)
每個案例給：前置 / 動作 / 預期 / 為何重要。
最後標出哪 5 個是「上線必過」、哪 5 個可延後自動化。
```

</div>

<br>

**AI 強**：test case 展開、自動化 script、stub / mock 資料、回歸表。
**AI 弱**：定義 invariant、判斷哪個 bug 阻擋上線、安全攻擊面。
**陷阱**：AI 生的 test 都是「正常 case」—邊界 / 並發要人特別逼問。
