> 給已具備基本系統設計概念的工程師——學習如何在商業與技術間做架構決策。

| 項目 | 說明 |

## 主角案例：即時 IoT 設備監控系統

全課程圍繞同一個主角系統逐幕演進，架構白皮書從 v0 成長到 v5。

### 共用設定數字（全課沿用）

| 項目 | 數值 |
|------|------|
| 系統類型 | 工廠設備即時監控 SaaS（B2B） |
| 設備規模 | 10,000 台設備 |
| 上報頻率 | 每台每 5 秒上報 |
| 平均訊息速率 | ~2,000 msg/s |
| 尖峰訊息速率 | ×3 ≈ 6,000 msg/s |
| 每筆大小 | ~200 B |
| 日資料量 | ~35 GB/天 |
| SLA：告警延遲 | P99 < 10 秒 |
| SLA：可用性 | 99.9% |
| 停機成本 | 每小時非計畫停機損失 ~$20,000 |
| 團隊 | 6 人（熟 Python、剛碰雲） |
| 初期雲費上限 | < $5,000/月 |
| 交付目標 | 3 個月交付 MVP |

> 這組數字在 Ch0 定義後，後續各幕**不再重新引入**，直接沿用。

## 五幕地圖

| 章 | 幕名 | 架構白皮書產出 | 核心任務 |
|---|------|--------------|---------|
| Ch0 | 接案世界觀 | v0：空白委託書 + VCRE 計分卡 | 認識架構師角色；發放 VCRE 四維計分卡 |
| 幕 1 | 需求與約束 | v1：PRD + NFR 矩陣 + 約束清單 | 把模糊業務訴求逼成可量化的需求文件 |
| 幕 2 | 建模與選型 | v2：領域模型 + 技術棧 + ADR-001 | 畫出業務領域 ER；做第一個技術選型決策 |
| 幕 3 | 系統設計 | v3：C4 圖 + API 草稿 + 資料流 | 從容器層設計到關鍵讀寫路徑 |
| 幕 4 | 風險與韌性 | v4：風險評估 + 故障模式分析 | 在圖上標出 SPOF；量化每個風險的 VCRE 代價 |
| 幕 5 | 落地與演進 | v5：開發規範 + 可觀察性 + 演進路線 | 決定上線標準；設計可觀察性；規劃三年路線圖 |
| Capstone | 白皮書整合 | v1→v5 完整演化 + 一頁式白皮書 | 從需求到演進，完整回顧決策鏈 |

## 白皮書演化總表

```
v0（Ch0）   空白委託書——只有業務痛點，沒有技術答案
v1（幕 1）  PRD + NFR + 約束清單（功能需求 / 非功能需求 / 資源約束）
v2（幕 2）  領域模型 ER + 技術棧比較 + ADR-001（資料儲存選型）
v3（幕 3）  C4 容器圖 + API endpoints 草稿 + Ingest/Query/Alert 資料流
v4（幕 4）  v3 圖加 warning 標記 + 風險矩陣 + 故障模式分析（FMEA）
v5（幕 5）  開發規範 + 可觀察性資料流（Metrics/Trace/Log）+ 演進路線圖
```

每幕只新增「一份核心產出物」，前一版本的所有圖/文件保持不變。Capstone 能默寫 v1→v5 完整白皮書。

## 雙螺旋設計

本課程有兩條線索貫穿所有章節，互相強化：

### 螺旋一：架構白皮書逐幕生長

- 每幕結尾有「補白皮書」回顧練習：學員只需在上一版加一份產出物
- 結業時能默寫完整 v1 → v5 白皮書
- 進度膠囊格式：`[ 架構白皮書 vN · 幕名 ]`（Mint 文字 + Deep Navy 底 + 圓角膠囊）

### 螺旋二：VCRE 計分卡

Ch0 發放四維計分卡；每個架構決策都從 VCRE 四維評分，凸顯「沒有絕對最佳解，只有取捨」。

| 維度 | 縮寫 | 白話問法 |
|------|------|----------|
| 商業價值 Value | V | 這個決策替業務賺錢/省錢/降風險嗎？ |
| 成本 Cost (TCO) | C | 總體擁有成本多少？（雲費 + 人力 + 維運） |
| 風險 Risk | R | 會壞在哪？SPOF？流量暴增 10 倍撐得住？ |
| 可演進 Evolvability | E | 三年後要改，這決定會卡住我們嗎？ |

## 如何閱讀本課程內容

- 原始草稿：每章一個 `slides.md`，保留完整敘事脈絡
- 產圖規格：每張投影片一個 `slide-XX.md`，可直接作為批量產圖輸入
- 每頁規格含 frontmatter、On-slide Text、Beginner Anchor、Visual Spec、GPT Image Prompt、Negative Prompt、Speaker Notes、QA Checklist
- 取捨拍（`layout_type: tradeoff`）額外含 VCRE Scorecard
- `layout_type: artifact` 的頁面必須使用 `Diagram Spec` 程式化渲染，不交給圖片模型自由生成拓樸
- 視覺風格：PPT 16:9 投影片（1920 × 1080 px）
- 製作時請搭配 `0_STYLE_GUIDE.md` 確保字型、色票、邊距一致

## 產圖工作流

1. 讀取單頁 `slide-XX.md`。
2. 使用 frontmatter 決定產圖方式：
   - `rendering_mode: image_prompt`：可交給 GPT Image 2 產生插畫 / 版面底圖。
   - `rendering_mode: programmatic_diagram`：先用 `Diagram Spec` 產生 SVG / HTML / 其他向量圖，再套用品牌樣式。
3. 若頁面有 `Logo Assets`，使用核准的官方 logo asset 後製疊上，不讓模型仿製品牌標誌。
4. 若頁面有 `Technical Flow Details`，確認最終圖完整呈現讀寫路徑、非同步行為、失敗處理。
5. 最終中文字、logo、頁尾與精準產出物圖建議由模板或程式化流程疊上，不依賴圖片模型臨場生成。
6. 出圖前跑每頁 `QA Checklist`，尤其檢查：
   - 標題字數（≤ 14 字）
   - 進度膠囊為「架構白皮書 vN · 幕名」
   - 官方 logo 素材到位
   - 技術流程嚴謹
   - **投影片上無任何來源/出處標註**
   - **投影片上無具名引導裝置字樣**
