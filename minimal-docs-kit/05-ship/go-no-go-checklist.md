# Go / No-Go Checklist — 五節點檢核表

> 卡片:`go-no-go-checklist` · 五節點的簽核紀錄。
> 節點之間隨你並行、探索、vibe;節點本身不容跳過。
> 每個節點可以很輕(小專案十分鐘一個),但要留下打勾紀錄。

## 節點 1:澄清(生成之前)

- [ ] `02-define/prd.md` 前三節已填(問題、成功標準、範圍)
- [ ] Out of Scope 至少寫了一條 <!-- 寫不出來代表還沒想清楚 -->
- [ ] 意圖負責人是誰,講得出名字

## 節點 2:決策(鋪開之前)

- [ ] 主要技術方向已寫進 `03-design/adr.md`(至少:語言/框架、資料存放、部署形態)
- [ ] 每則決策都有「不選什麼」那一行
- [ ] `CLAUDE.md` 已放到專案根目錄,AI 讀得到

## 節點 3:凍結(並行之前)

只有多人 / 多 agent / 前後端並行時才需要;solo 單線開發可標 N/A:

- [ ] `03-design/api-spec.yaml` 標記 Frozen,consumers 已通知
- [ ] `03-design/data-model.md` 標記 Frozen,migration 可回滾已驗過
- [ ] 契約能生成 mock,各端可以不等彼此開工

## 節點 4:驗證(宣稱完成之前)

- [ ] `02-define/acceptance-criteria.md` 的 Exit Criteria 逐條有證據
- [ ] 「把實作改壞、測試會紅」抽查做過
- [ ] 驗收簽名的人 ≠ 主要生成程式的那個 agent/人

## 節點 5:退路(上線之時)

- [ ] 回滾方式寫得出來,而且演練過一次(不是「應該可以 revert」)
- [ ] 最低限度的觀測:錯誤率 + 延遲看得到,壞了會有人知道
- [ ] 上線後第一個小時,誰在看盤,講得出名字
