# ADR — 決策日誌

> 卡片:`adr` · 文件 2/4:治「AI 失憶與漂移」的唯一解。
> 一則決策 5–10 行就夠;沒寫下來的決策等於不存在,下次生成會被推翻。
> 填寫人:決策負責人。新決策往上加,舊決策不刪改,只標 Superseded。

## 格式

```
## D-<編號> <標題>            (Accepted | Superseded by D-x)  <日期>
背景:一兩句,為什麼需要決定
決定:選了什麼、適用範圍
不選:排除了什麼、為什麼          ← 這行防止 AI 下次把被否決的方案再端上來
代價:接受了什麼缺點 / 後續要做什麼
```

---

## D-1 <範例:資料庫選 PostgreSQL,不用 MongoDB>  (Accepted) 2026-08-12

- 背景:訂單與庫存需要交易一致性,查詢模式以關聯為主。
- 決定:主資料庫用 PostgreSQL 15+,所有 schema 變更走 migration 檔。
- 不選:MongoDB——文件模型對本案的多表一致性是負資產;
  也不選 SQLite——需要多實例並行寫入。
- 代價:本地開發環境需要 docker compose 起 DB;接受之。
