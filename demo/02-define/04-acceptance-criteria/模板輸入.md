## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **AC 必須是機械可驗證的 Given / When / Then**。禁止「順、好用、合理、清楚」這類主觀字眼 — QA 沒法把這種句子翻成 Jest / Playwright assertion。
- **每條 P0 FR 至少 1 happy_path + 1 error_path + 1 NFR 對應 AC**。只寫 happy path 是教學情境最常見的偷懶。
- **Edge cases 至少 3 條，且要對應到 PRD §7 Risks 或 §6 NFR 真實風險**，不能編造不會發生的情境湊數。MVP 不適用的類型（如 concurrency / perm_denied）要寫進 Decision Log 並註明何時要補。
- **`Error Handling` 每條都要有 error_code + user_message + log_level + retry_policy 四欄**。retry_policy 必須是 enum（none / immediate / exponential_backoff），不能寫「再試」這種模糊詞。
- **NFR AC 必須涵蓋 perf + a11y + security + audit 四象限**，且 perf 要附「量測點」（不只是數字 — 例如 Performance.mark from "submit_click" to "tier_cards_rendered"）。
- **`mockable: false` 的 AC 必須跑 contract test / real-device test**，不可省。本卡 FR-004（即時匯率 happy path）就是典型 — 只 mock 會錯失 SLA 與格式驗證。

### User story（取自 03-prd FR-002/003/004 + JTBD-001）

**作為**衝動型出境旅客（25–40 歲、預算敏感、習慣帶現金），
**我想要**在 3 分鐘內看到「該換多少外幣現金 + 現在換划不划算」，

本卡聚焦 **FR-002（建議換匯現金額）+ FR-003（FX 換匯燈號）+ FR-004（即時匯率資料源）** 三條 P0 需求（這是 SmartTrip FX 護城河的核心三件套）。

### PRD 文件（取自上游 03-prd 實際結果摘錄）

**FR-002 建議換匯現金額**：

- 建議額 = 該方案 cash_only 行程總和 × 1.1（10% 緩衝）
- 依目的地幣別進位（JPY 進位至 1000、KRW 進位至 10000）
- priority: P0, confidence: `[H]`, source: brief §待解痛點 + JTBD-001

**FR-003 FX 換匯燈號**：

- 燈號邏輯：今日匯率 vs MA30 偏離 %（STRONG_BUY / BUY / HOLD）
- 畫面附「非投資理財建議」免責聲明
- priority: P0, confidence: `[H]`, source: brief §業務約束 + 期望成果

**FR-004 即時匯率資料源**：

- 燈號與匯率來自真實 API
- API 失敗時降級到快取，畫面標「模擬」
- priority: P0, confidence: `[H]`, source: brief §業務約束 P0-8

**NFR 摘錄**：

- **Latency**：行程生成端到端 p95 < 3 秒；FX 燈號讀取 p95 < 500ms
- **A11y**：WCAG 2.2 AA（戶外通勤手機使用，對比度與可觸控區域）
- **Security**：data_classification: internal；主要威脅 XSS + 第三方匯率 API 偽造
- **Audit**：分析事件 90 天無 PII；FX 燈號須符合金管會「非投資理財建議」標示

**合規要求**：
FR-003 顯示燈號時須包含「非投資理財建議」免責聲明（業務約束 §法規）。

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`，並先跑完 [`03-prd/`](../03-prd/) 拿到 PRD（含 FR + NFR）
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（從你的 PRD 挑 2–4 條 P0 FR，把 User story / PRD section / mock 清單 3 個小節換成你自己的對應內容）
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
