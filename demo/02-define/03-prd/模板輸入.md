# 03-PRD · 模板輸入

> **這個檔案怎麼讀**：
>
> 1. 先看 **本卡注意事項** — 進 Claude 前要記在腦袋裡的 4-5 條
> 2. 再看 **上游文件對照** — 學會 trigger 的「上游文件」貼位區要塞什麼
> 3. 然後跟著 **完整 prompt** 的 3 步驟組裝、貼到 Claude（等 40-60 秒）
> 4. 拿到結果後對照 [`實際結果.md`](./實際結果.md) 的真實 PRD markdown 樣
> 5. 最後看 **接棒下游** — 知道這份輸出要餵給後面哪幾張卡

---

## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **輸出是真實 PRD markdown 文件，不是 YAML**。對標 Linear / Amplitude / Atlassian 業界規格 — 含表格、Mermaid 流程圖、inline `[H/M/L]` confidence badge、10 段 H2 章節。看到 AI 想吐 `yaml` code-fence 就是錯的。
- **P0 / P1 / P2 切分要對應上游 value-hypothesis 的 Riskiest Assumption**。P0 必須足以驗證 riskiest，否則 4 週 MVP 收的數據無意義。最常見錯誤：把「使用者會喜歡的功能」當 P0。
- **`Counter-metric` 防 goal-hacking**。若只看啟用率，PM 會拉長流程衝啟用率，破壞「3 分鐘完成」門檻。counter_metric 必須對應一個 JTBD 互斥。
- **NFR 4 象限**（latency / a11y / security / audit）任一缺失要在 Rationale 欄寫明為何不適用，不能直接砍。
- **每個 FR / NFR / Goal 必須有 inline `[H]` / `[M]` / `[L]` badge** + 行內 `（依據：brief §XXX / JTBD-NNN）` 可追溯。沒 badge 的欄位 lint 會抓。
- **Decision Log 每條 ≥ 2 個 rejected options + 各自 Rejected why**。只寫 chosen 沒有捨棄選項 = 黑箱。

## 上游文件對照（站上 trigger 的「上游文件」貼位區應該裝什麼）

PRD 是承上啟下的中樞，貼位區要塞**整份上游 markdown 文件**（不再剪貼個別 YAML 欄位）：

| 上游 input（範本要求） | 我們在 SmartTrip 範例填入的內容 |
|---|---|
| **Project Brief** | 完整貼進 SmartTrip FX 的 brief markdown（5 段：目標受眾 / 待解痛點 / 期望成果 / 主要約束 / 成功指標） |
| **JTBD 文件** | 完整貼進 [`../../01-discovery/01-jtbd/實際結果.md`](../../01-discovery/01-jtbd/實際結果.md) 的 AI 輸出 markdown |
| **Value Hypothesis 文件** | 完整貼進 [`../../01-discovery/02-value-hypothesis/實際結果.md`](../../01-discovery/02-value-hypothesis/實際結果.md) 的 AI 輸出 markdown |
| **Journey Map（選填）** | 教學情境無正式 journey map，這邊改貼從 JTBD-001 + brief 痛點推出的 6 段旅客 journey（簡化版） |

> **學生對照重點**：
> - 過去你要從 jtbd YAML 翻找 `JTBD-001.success_criteria.[0]` 然後剪貼進 PRD prompt 的 input 區 — 那是 chaining DAG 思維
> - **新思維是**：把整份 `jtbd 實際結果.md` 完整貼進去就好。LLM 自己會讀、自己會找到 success_criteria、自己會交叉印證
> - 這就是「document-driven context injection」— 像在 Cursor / Claude Code 裡讓 agent 讀整份文件

### Project Brief

# SmartTrip FX 種子簡報

#### 目標受眾

25–40 歲台灣衝動型出境旅客，一年 1–4 趟、以日韓泰為主、預算敏感、習慣帶現金、決策快怕麻煩。次要族群：第一次自由行的新手。

#### 待解痛點

不知道該帶多少外幣現金、哪些地方只收現金、現在換匯划不划算。換太多 → 回國再換虧匯差；換太少 → 現場狼狽。在一趟 NT$40,000 的旅程中，匯損與多換的成本可達數百到上千元。現有行程規劃工具與 OTA 完全不處理這件事，旅客只能憑感覺換匯。

#### 期望成果

3 分鐘內得到一份含「精準建議換匯現金額」的行程，且事後實際現金花費與建議值誤差 < 15%。讓使用者出國前對「該帶多少錢」這個決策不再焦慮。

#### 主要約束

- 不做帳號雲端同步（MVP 用 localStorage）
- 不做訂房比價或庫存查詢（用外部連結導出）
- 4 週 MVP 驗證窗
- FX 燈號需「非投資理財建議」免責聲明
- 既有 v0.1 已上線，P0-8（即時匯率）+ P0-9（基本分析）尚未完成

#### 成功指標

- 啟用率 ≥ 40% / 存檔率 ≥ 25% / 30 天回訪 ≥ 20% / 換匯誤差 < 15% 比例 ≥ 60%

### JTBD 文件

（在這裡完整貼進 `01-jtbd/實際結果.md` 的 AI 輸出 markdown 文件。包含 JTBD-001 到 JTBD-005、Mutually Exclusive Jobs、Decision Log、Out of Scope、Confidence & Sources 全文）

### Value Hypothesis 文件

（在這裡完整貼進 `02-value-hypothesis/實際結果.md` 的 AI 輸出 markdown 文件。包含 Riskiest Assumption / Kill Criteria / Leading Indicator 全文）

### Journey Map（選填）

從 JTBD-001 + brief 待解痛點推出的旅客 journey（教學簡化版）：

1. 看到廉航特價 → 興奮買票（trigger）
2. 出發前 1–2 週查資料 → 切換 Google / IG / Klook / 部落客（pain：資訊散亂）
3. 出發前 3–5 天決定行程 → 拍板（pain：不知道金錢需求）
4. 出發前 1–2 天去換錢 → **憑感覺換**，常多換或少換（CORE PAIN）
5. 旅途中 → 想記帳但麻煩，事後超支才發現（pain：被動）
6. 回國 → 把多換的外幣換回，認虧匯差（pain：事後懊悔）

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載 `project-brief.md`，並先跑完 [`01-jtbd/`](../../01-discovery/01-jtbd/) 與 [`02-value-hypothesis/`](../../01-discovery/02-value-hypothesis/) 拿到上游兩份 markdown 輸出
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（4 個小節：Project Brief / JTBD 文件 / Value Hypothesis 文件 / Journey Map，整段換成你自己的對應內容）
4. 貼到 Claude → 對比你拿到的 markdown PRD 文件與 [`實際結果.md`](./實際結果.md) 的結構

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
