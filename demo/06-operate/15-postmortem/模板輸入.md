## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **Blameless：寫流程/工具/訓練/設計缺口，不寫人名作為根因**。個人錯誤一律歸因於「系統未保護該操作」（範本 `> [!IMPORTANT]` 規則）。`Blameless Summary` 出現具體人名就要重寫。
- **5 Whys 必須終止於系統性原因**（process / training / monitoring / design），不能停在「人沒注意到」。停在人 → action item 只剩「下次小心」，沒人能驗證。
- **每個 `Action Items` 必須有 `owner` + 具體 `due` date + `tracking_link` + `success_criteria`**。個人專案 owner 寫「我自己」，但 due 不可寫「ASAP」。
- **`Prevention Categories` 4 類必須齊全**（detection / response / recovery / prevention）。無缺口的類別誠實寫「本次非主要缺口」，不可整類省略 — 學生最常漏 detection / response。
- **`SLO Burn` 個人專案無 SLO 就寫 `N/A — 無正式 SLO`**，不要編造百分比。

### Incident Report

**Incident ID**: INC-2026-0530-01
**Severity**: SEV-2
**Service**: SmartTrip FX
**Affected**: 約 200 名有機流量使用者（依 Vercel Analytics 估算）
**Duration**: 12 小時（2026-05-30 02:00 ~ 14:00 UTC+8）

**Summary**：FX 換匯燈號連續 12 小時顯示「模擬資料」badge 而非真實匯率，但顯示給使用者的數字是 exchangerate.host 在 2026-05-29 23:50 拉到的快照（已過期 ~14 小時）。約 200 名使用者基於此資料做了換匯決策，預估影響金額：人均誤差 < 0.5%（外幣本身波動小），但**「燈號顯示模擬卻仍呈現過期真實數字」的不一致違反了 PRD P0-5 與合規承諾**。

**Impact**：
- 200 名使用者看到失準資料
- 違反 release plan 的 success_criteria 第 1 條（FX 燈號渲染成功率 ≥ 95%）
- 無 PII 洩漏、無資料丟失
- 商業影響：無付費用戶，但對「金錢優先」差異化定位的信任造成可量化傷害（GitHub 收到 3 個 issue）

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. **檢查前提**：postmortem 是 reactive deliverable — **沒有真實事故就不要寫**。學生若是教學情境可像本範例用「假設未來某 ALERT 觸發」演示，但要在頁面顯式標明是假設。
2. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`
3. 步驟 1（複製站上「完整範本」tab）**完全不動**
4. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**：
   - 把「Incident Report」換成你自己的真實事故 metadata（ID / severity / users affected / duration）
   - 把「Chat log」換成你 Slack / Obsidian 的當下記錄（時間戳保留 → AI 才能抽 timeline）
   - 把「Runbook 執行紀錄」換成 oncall 實際做了什麼，特別是**設計 vs 實作偏離**那段（這是 postmortem 最常見的金礦）
5. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
