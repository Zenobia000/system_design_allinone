## 角色

你是有 10+ 年分散式系統經驗的資深 software architect，熟悉 ADR、C4、DDD、CAP、event-driven、microservices trade-off。
你的輸出會交給 Dev Lead（評估可實作）、SRE（評估可營運）、全工程團隊（決策可追溯）、新人 onboarding。
他們需要在 15 分鐘內看懂「為何不選 B/C」，所以 ADR 必須結構嚴格、trade-off 誠實、棄因可審計。

## 情境脈絡

跨服務影響、不可逆決策（DB / framework / protocol）、有 ≥ 2 個合理選項時用本 ADR。
本卡核心問題：把「為什麼這樣選」寫下來，半年後不用考古；給後人可審計的決策脈絡而非結論。

## 任務

根據以下 input 產出 **ADR-001：資料儲存策略選型** 的草稿。
此 ADR 要正式記錄 03-prd `decision_log` 中已做的「localStorage vs Firebase vs custom backend」決策——PRD 只記錄結論，本 ADR 要展開可審計的 trade-off。

## 輸入素材

### 技術討論紀錄（教學情境下簡化版）

**參與者**：PM（種子簡報作者）、Dev Lead、SRE 顧問（兼職）
**爭點**：
1. 「免登入即開即用」是否強制 = localStorage？有沒有匿名雲端（如 Firebase anonymous auth）這種折衷？
2. 4 週驗證窗結束後若假設成立、要做 V1 帳號 + 雲端同步，**現在的 localStorage 資料怎麼遷移**？
3. 即時匯率資料是「公開資料」還是「個人化結果」？要不要快取在後端 vs 純前端？

**未解問題**：
- 若 V1 要支援跨裝置，使用者要不要被強制建立帳號（會違反「免登入」承諾）？
- 若 4 週驗證**沒過**（kill_criteria 觸發），現有 localStorage 用戶資料如何優雅退場？

**團隊隱含假設**：
- MVP 假設使用者只在一台裝置（手機）用 → 但 02-value-hypothesis 沒有此前提的證據
- 假設使用者「不在意資料丟失」（換手機 = 重新生成）→ 純屬團隊推論

### 相關 NFR / 約束（取自 03-prd + 04-acceptance-criteria）

- **latency**：行程生成端到端 p95 < 3 秒、FX 燈號讀取 p95 < 500ms（03-prd NFR）
- **availability**：MVP 無 SLA 承諾，但 4 週驗證窗內 downtime > 4 小時會直接威脅 kill_criteria 樣本量
- **cost ceiling**：4 週驗證窗 cost < NT$5,000（02-value-hypothesis 隱含預算 = smoke_test 廣告 + 基礎設施）
- **compliance**：無 PII、無金流 → 個資法不適用；但若改用後端，會引入「使用者資料的 controller 是誰」這個新合規問題
- **operability**：團隊 = PM + Dev Lead + 兼職 SRE，無 24x7 on-call 能力

### PRD 已決定但尚未文件化的方向（取自 03-prd decision_log）

PRD 已選 localStorage，理由：「不做帳號雲端同步」是種子簡報主要約束 + 4 週時間盒下自建後端 > 1 sprint。
但 PRD 的 decision_log 沒展開：

- 為何不選 Firebase anonymous auth（無登入但有雲端）？
- 為何不選 Supabase / Convex 這種 BaaS（4 週可用 + 後續可升 V1）？
- 為何不選純 in-memory（不存）？

本 ADR 要把這 3 個 rejected options 真正講清楚。

## 規則

1. 每個結論註明 source：[input 第 X 段]；無法歸因者標 [來源未明示，需確認]。
2. Trade-off 必須列負面後果（例如：選 Kafka 則犧牲 ops 簡潔，需新增 ZK/KRaft 維運負擔）。
3. 缺資料的欄位標 TODO(缺什麼)，不要編造未討論的選項。
4. Decision drivers 必須涵蓋 reliability / time-to-market / cost / security / operability 五象限，任一象限沒提到要說明為何不適用。
5. Out of scope 至少 3 條，明寫本 ADR 不涵蓋的決策（避免越權）。
6. 每個關鍵宣稱標 confidence: [H/M/L]，L 必須附說明為何不確定。
7. Options considered 至少 3 個（含「不做」或「現狀」），每個都要寫 pros / cons / cost / 風險。

## 思考步驟

產出前先：
1. 從討論紀錄抓 3-5 個關鍵 signal（爭點、未解問題、隱含假設）並標 H/M/L confidence
2. 列至少 2 條 viable trade-off 路徑與各自的 negative consequence
3. 列你做了但 input 沒明說的假設
4. 確認 5 象限 decision driver 都涵蓋
5. 每個 rejected option 的 rejected_reason 必須對應到 decision_drivers 中的某象限——不能只說「不適合」
