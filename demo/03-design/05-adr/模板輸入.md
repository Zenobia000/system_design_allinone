## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **`Options Considered` 至少 3 個**，且**必須包含「不做 / 現狀」這種下界對照**。只列 chosen + 1 個 strawman option = 看不出真實取捨。
- **`Decision Drivers` 五象限（reliability / time_to_market / cost / security / operability）都要寫 weight + rationale**。不適用的象限要寫「為何不適用」，不能省略。
- **`Rejected why` 必須對應到具體的 decision driver 象限**，不能只寫「不適合」「不夠好」這種空話。例：「operability driver: 需要 24x7 on-call，本團隊無此能力」。
- **`Consequences §Negative` 必填**，選了 A 一定犧牲什麼，誠實寫出來；只寫 positive 是黑箱。
- **`Status` 若標 `accepted`，必須寫 `Review date`**，特別是綁時間盒的決策（如 MVP 驗證窗）。不寫等於不維護，新人會誤以為現在還適用。
- **ADR 只寫 what & why，不寫 how**。schema 設計 / 序列化格式 / 加密策略屬於 Dev Lead 實作層，不該進 ADR。

⏬

### 技術討論紀錄

**參與者**：PM、Dev Lead、SRE 顧問（兼職）

**爭點**：

1. 「免登入即開即用」是否強制 = localStorage？有沒有匿名雲端（如 Firebase anonymous auth）這種折衷？
2. 4 週驗證窗結束後若假設成立、要做 V1 帳號 + 雲端同步，**現在的 localStorage 資料怎麼遷移**？
3. 即時匯率資料是「公開資料」還是「個人化結果」？要不要快取在後端 vs 純前端？

**未解問題**：

- 若 V1 要支援跨裝置，使用者要不要被強制建立帳號（會違反「免登入」承諾）？
- 若 4 週驗證**沒過**（kill_criteria 觸發），現有 localStorage 用戶資料如何優雅退場？

**團隊隱含假設**：

- MVP 假設使用者只在一台裝置（手機）用 → 但上游 02-value-hypothesis 沒有此前提的證據
- 假設使用者「不在意資料丟失」（換手機 = 重新生成）→ 純屬團隊推論

### 相關 NFR / 約束（取自上游 03-prd §6 + 04-acceptance-criteria §Performance Thresholds）

- **Latency**：行程生成端到端 p95 < 3 秒、FX 燈號讀取 p95 < 500ms（PRD §6 NFR）
- **Availability**：MVP 無 SLA 承諾，但 4 週驗證窗內 downtime > 4 小時會直接威脅 kill_criteria 樣本量
- **Cost ceiling**：4 週驗證窗 cost < NT$5,000（02-value-hypothesis 隱含預算 = smoke_test 廣告 + 基礎設施）
- **Compliance**：無 PII、無金流 → 個資法不適用；但若改用後端，會引入「使用者資料的 controller 是誰」這個新合規問題
- **Operability**：團隊 = PM + Dev Lead + 兼職 SRE，無 24x7 on-call 能力

### PRD 已決定但尚未文件化的方向（取自 03-prd §8 Decision Log）

PRD 已選 localStorage，理由：「不做帳號雲端同步」是主要約束 + 4 週時間盒下自建後端 > 1 sprint。
但 PRD 的 Decision Log 沒展開：

- 為何不選 Firebase anonymous auth（無登入但有雲端）？
- 為何不選 Supabase / Convex 這種 BaaS（4 週可用 + 後續可升 V1）？
- 為何不選純 in-memory（不存）？

本 ADR 要把這 3 個 rejected options 真正講清楚。

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`，並先跑完 [`03-prd/`](../../02-define/03-prd/) + [`04-acceptance-criteria/`](../../02-define/04-acceptance-criteria/) 拿到上游輸出
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（4 個小節：技術討論紀錄 / 相關 NFR / PRD 已決定方向 / 已存在的連結，換成你自己的對應內容）
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
