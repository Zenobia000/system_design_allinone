## 角色

你是有 10+ 年分散式系統經驗的資深 software architect / SRE，熟悉 SLO / SLI / error budget、WCAG 2.2、SOC 2、GDPR、HIPAA、PCI DSS、ISO 27001、observability、ISO/IEC/IEEE 29148。
你的輸出會交給 Dev（實作目標）、QA（寫驗收測試）、SRE（設 alert 與 SLO dashboard）、Compliance（合規稽核）。
他們需要每條 NFR 都可量測、可測試、可監控；模糊形容詞會被退件。

## 情境脈絡

功能規格已寫，但延遲、容量、可用性、安全還只是形容詞時用本 NFR。
本卡核心問題：把「要很快、要很穩」改寫成可驗收的數字，是 ADR 與 Capacity Plan 的輸入。

## 輸入素材

### PRD 中的模糊承諾（待改寫為可量測 SLI/SLO）

從 PRD 抓出的形容詞清單：

- 「**3 分鐘內**得到一份含建議換匯額的行程」（G1 / §7 領先指標）— **可量測**
- 「**精準**建議換匯現金額」 / 「換匯**準確度**」— 模糊，需轉成 SLI
- 「FX 燈號**夠用、可信**」（G4）— 滿意度問卷 + SLI
- 「P0-8 失敗時**明確標示『模擬』**」— 可改寫為 availability SLO
- 「**免登入、即開即用**」（種子簡報 主要約束）— 可改寫為 page load p75 + a11y
- 「**重隱私**」（PRD §9 P0-9 Open Question）— 改寫為 data classification 控制

### Business impact / SLA 對外承諾 / penalty clause

- 4 週 MVP 驗證窗，啟用率 ≥ 40% + 30 天回訪 ≥ 20% 為「假設成立」門檻（PRD §7）
- 無對外 SLA（個人工具、無付費客戶）
- 法務：FX 燈號需「非投資理財建議」免責聲明（PRD §9 Open Question 第 6 條）

### 既有 NFR / 平台基線 / 競品 baseline

- Vercel 免費方案：邊緣節點全球分布，free tier 100GB bandwidth / 月
- Plausible：99.9% SLA（vendor 自報）
- 競品 baseline：KKday / Klook 行程頁首屏 ~2-4s（業界經驗值，無正式報告）

### 上游卡輸出（PRD G1 + Success Metrics）

- 3 分鐘完成 → 拆解為 page load + API + interactive render 預算
- 換匯誤差 < 15% 比例 ≥ 60% → 落後指標，需 P0-9 上線後校準

### 上游卡輸出（C4 + API spec 摘要）

- 端點：`GET /api/v1/fx/rate`、`POST /api/v1/analytics/event`
- 依賴：FX provider（vendor 待定）、Plausible
- localStorage 配額 ~5MB

### 上游卡輸出（Data Model 摘要）

- `Trip`、`ItineraryItem`、`Expense`、`FXRateCache` 四個 entity
- `data_classification`：destination / dates / note 為 session_sensitive
- `erasure`：使用者可「清空所有資料」

## 規則

1. 每條 NFR 註明 source：[input 第 X 段]；無法歸因者標 [來源未明示，需確認]。
2. Trade-off 必須列負面後果（例：p95 < 100ms 則犧牲 cost — 需 over-provision 或 CDN edge）。
3. 缺資料的欄位標 TODO(缺什麼)，不要抄業界數字（例：別寫「99.99% 因為大家都這樣寫」）。
4. 合規 / a11y / security 必須涵蓋：GDPR / SOC 2 / PCI / HIPAA / ISO 27001 / WCAG 2.2 AA（任一不適用要說明原因）。
5. Out of scope 至少 3 條（例：第三方依賴 SLA、災難復原 RPO/RTO、客戶端 a11y 不在本卡）。
6. 每條 NFR 標 confidence: [H/M/L]，L 必須附說明。
7. 每條 NFR 必含可量測 SLI + 目標 SLO + 量測方法 + 測試方式（缺一不可）。

## 輸出格式（YAML）

latency_targets:
  - sli_name: <e.g. page_load_lcp_p75>
    slo_target: <number + 單位 + 「為何此值」>
    measurement: <RUM / synthetic / server-side timing>
    test_method: <Lighthouse CI / k6 / playwright trace>
    source: <input ref>
    confidence: H | M | L
    trade_off: <達成此目標犧牲什麼>

availability_slo:
  - sli_name: <e.g. fx_endpoint_success_rate>
    slo_target: <%>
    error_budget: <derived>
    scope: <which endpoint / journey>
    measurement: <SLI definition>
    test_method: <synthetic probe / status page>
    source: <input ref>
    confidence: H | M | L

scalability:
  baseline_traffic: <e.g. 100 DAU at MVP launch>
  peak_rps: <number + 來源>
  concurrent_users: <number>
  scale_strategy: <e.g. Vercel auto-scale Edge + cache>
  trade_off: <負面後果>
  source: <input ref>

reliability:
  - sli_name: <e.g. fx_simulated_fallback_correctness>
    slo_target: <e.g. 失敗時 100% 顯示「模擬」標記>
    measurement: <how>
    test_method: <chaos test / e2e test>

security_classification:
  data_classes: [<list>]
  threat_baseline: <ref threat-model 或寫 [來源未明示]>
  encryption: <at-rest + in-transit>
  controls: [<列出對應控制>]
  confidence: H | M | L

privacy:
  pii_inventory: [<列出可能視為 sensitive 的欄位>]
  retention_policy: <如何處理>
  user_erasure_flow: <UI + 技術實作>
  consent_model: <e.g. analytics opt-in>

compliance_obligations:
  gdpr: <條款 + 對應控制 | N/A + 原因>
  soc2: <trust criteria + 對應控制 | N/A + 原因>
  pci: <requirement + 對應控制 | N/A + 原因>
  hipaa: <safeguard + 對應控制 | N/A + 原因>
  iso_27001: <annex A control + 對應控制 | N/A + 原因>

a11y:
  level: WCAG 2.2 AA
  scope: <web / mobile / both>
  key_criteria: [<列出重點 success criterion>]
  testing: <e.g. axe-core CI + 手動鍵盤瀏覽>

cost:
  monthly_budget_ceiling: <number + 來源>
  driver_metrics: [<FX provider calls / Vercel bandwidth / Plausible events>]
  scale_with: <什麼指標成長會推升成本>

operability:
  observability_requirements:
    metrics: [<SLI 1>, <SLI 2>]
    logs: <retention + classification>
    traces: <sampling rate>
    alerting: <SLO burn rate threshold>
  on_call: <MVP 是否有 on-call>
  runbook_required_for: [<incident type>]

decision_log:
  - decision: <e.g. 選 99.5% 而非 99.9%>
    options_considered: [A, B, C]
    chosen: A
    rejected_reason:
      B: <why not, 含 cost / complexity>
      C: <why not>
    confidence: H | M | L

out_of_scope:
  - <條目 1>
  - <條目 2>
  - <條目 3>

self_review:
  lowest_confidence:
    - field: <欄位>
      reason: <why low>
      need: <what's needed>
  fabricated_assumptions:
    - <input 沒明說但我假設了的>
  highest_value_next_input: <下一份最該補的 input>
