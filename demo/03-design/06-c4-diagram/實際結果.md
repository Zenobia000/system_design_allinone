## 教學要點（看完 AI 輸出後讀這段）

### 1. 為什麼這張卡同時畫了 Level 1/2/3，但沒畫 Level 4？

C4 的核心紀律是**每層服務一種讀者**。SmartTrip FX 規模小，Level 1 給 stakeholder（種子簡報的「PM 對 stakeholder 講故事」場景）、Level 2 給工程團隊看 container 邊界、Level 3 給新人看 lib/ 內部。Level 4（code 層）半年內必改，畫了即過時 — `decision_log` 寫得很清楚：**「畫了即過時，違反 C4 分層紀律」**。

如果學生強迫畫 4 層，會落入「每張圖都是義大利麵」的反模式。

### 2. 為什麼 FX Rate Provider 與 Plausible 標 `confidence: M`？

兩個都是 PRD Open Question 範圍：

- FX vendor 未拍板（PRD §9 第一條）
- Plausible 已決方向但未正式 ADR sign-off

**沒有 ADR 文件就誠實標 M**，不要為了讓圖看起來「完整」而美化成 H。`self_review.lowest_confidence` 對應一條補洞計畫（ADR-005 評估報告）。

### 3. `architecture_risks` 為什麼一定要 ≥ 3 條？

規則第 7 條要求至少 3 個架構風險點。這張卡列了 4 個，對應到 SmartTrip FX 真實的脆弱面：

| 風險 | 對應到種子簡報/PRD 哪一條 |
|---|---|
| FX provider 單點 | PRD P0-8 缺口 + 種子簡報「省錢」差異化 |
| localStorage 配額 | ADR-002 + PRD Non-Goals 「不做帳號雲端同步」 |
| chatty FX fetch | M-2 與 M-3 都需要 rate，是設計味道 |
| Analytics 靜默失敗 | PRD P0-9 缺口 |

學生若只列「效能可能會慢」「安全可能有問題」這類**沒有具體 element 對應**的風險，等於沒列。

### 4. 這張卡的輸出流向下游哪些卡

| 本卡欄位 | 流向哪張卡 |
|---|---|
| `elements` C-2 FX Rate Proxy + 規則 | `07-api-spec/` 的 `GET /api/fx/rate` endpoint |
| `elements` C-3 LocalStorage 三類資料 | `08-data-model/` Trip / Expense / FXRateCache entity |
| `architecture_risks` FX 單點 + analytics 靜默 | `09-non-functional-reqs/` availability_slo + observability |
| `decision_log` FX Proxy 不走 Edge runtime | `05-adr/` 補 ADR-003 細節 |
| `boundary_definitions` SmartTrip Web BC | `10-code-review-checklist/` 跨 boundary review 規則 |

## 學生常見錯誤（交件前自己對照）

| 錯誤 | 違反規則 | 怎麼修 |
|---|---|---|
| Level 1 圖塞進 `lib/budget` 這種 component | 規則 4（分層紀律） | Level 1 只放 system + actor + external；component 屬 Level 3 |
| 把 LocalStorage 畫在 SmartTrip System 外（因為它「在使用者瀏覽器」） | `boundary_definitions` rationale | 由本系統擁有 schema/version → 在系統內。物理位置不等於擁有權 |
| `architecture_risks` 寫「效能可能會慢」這類空話 | 規則 7 | 必須指名具體 element + 具體 follow_up（ADR/監控/重構） |
| Mermaid 圖只貼一張 `flowchart TD`，不用 C4Context/C4Container 語法 | notation.syntax | Mermaid 有原生 C4 語法（C4Context / C4Container / C4Component），用對的圖種 |
| 把 Vercel CDN 也畫進 Level 2 container | `omitted_details` 漏寫 | 部署拓撲屬另一張 deployment diagram，本卡應在 omitted_details 解釋為何省略 |

## 交件 checklist

- [ ] Level 1 圖只有 system + actor + external，沒混入 container/component
- [ ] Level 2 圖列出所有 container 與技術選型（且與 ADR 一致）
- [ ] Level 3 圖只在單一 container 內展開，不跨 container
- [ ] `architecture_risks` 至少 3 條，每條對應具體 element + follow_up
- [ ] `decision_log` 至少一條，列出 `options_considered` + `rejected_reason`
- [ ] `out_of_scope` 至少 3 條（Level 4、deployment、data model）
- [ ] 每個 `confidence: M/L` 都在 `self_review.lowest_confidence` 對應一條補洞計畫
- [ ] Mermaid 用 C4Context/C4Container/C4Component 語法而非通用 flowchart
