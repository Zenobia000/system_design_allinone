## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **分層紀律是 C4 的命根**：Level 1 只放 system + actor + external；Level 2 才放 container；Level 3 才放 component。任何混層 = 義大利麵，必須在 §Omitted Details 解釋。
- **每層對應一種讀者**。Level 1 給 stakeholder、Level 2 給工程團隊、Level 3 給新人 / code reviewer。沒讀者就不畫，**Level 4 (code) 預設不畫**（半年內必改、畫了即過時）。
- **`Architecture Risks` 至少 3 條**，且每條必須指名具體 element + 具體 follow_up（ADR / 監控 / 重構），不可寫「效能可能會慢」這種空話。
- **Mermaid 一定要用 C4 原生語法**（`C4Context` / `C4Container` / `C4Component`），不要用通用 `flowchart TD` 糊弄過去。
- **技術選型必須與 ADR 一致**。若 element 的 `tech` 與既有 ADR 衝突，要在 §Decision Log 解釋或開新 ADR。
- **`Boundary Definitions` 看擁有權，不看物理位置**。例：localStorage 雖在使用者瀏覽器，但 schema/version 由本系統管理 → 在系統 boundary 內。

### Codebase 結構 / 主要模組 / package 邊界

SmartTrip FX 是一個 Next.js 14 App Router 的純前端 SPA，無自有後端服務。主要 package 邊界：

- `app/` — Next.js 路由（`/`, `/start`, `/result`, `/my-trips`, `/expense/[id]`）
- `components/` — UI 元件（TripForm、TierCard、ItineraryTimeline、FXBadge、ExpenseList）
- `lib/fx/` — FX 燈號計算（今日 vs MA30 偏離 %）
- `lib/budget/` — 三方案產生器（Low/Mid/High）與建議換匯額（cash_only × 1.1）
- `lib/storage/` — localStorage adapter（Trip / Expense / FXRateCache）
- `lib/analytics/` — 事件發送（generate / save_trip / add_expense）
- 外部 API：FX rate provider（P0-8 待接入，目前為模擬資料）

### 既有 ADR 清單與技術選型

- **ADR-001**：採用 Next.js 14 App Router（SSG + ISR）— 來自主要約束「免登入、即開即用」
- **ADR-002**：MVP 不做後端，行程資料存 localStorage — 來自主要約束「不做帳號/雲端同步」
- **ADR-003**：FX 即時匯率走 server route handler 代理（避免 client 暴露 API key），快取 5 分鐘
- **ADR-004**：分析事件選 Plausible（無 cookie、輕量、符合隱私定位）
- **部署**：Vercel（已上線 <https://smarttrip-fx.vercel.app>）

### Stakeholder 清單與外部系統

- **主要 actor**：台灣出境旅客（25–40 歲，brief §目標受眾）
- **外部系統**：FX rate provider（候選 ExchangeRate-API / Open Exchange Rates，⚠️ vendor 未拍板，標 `[M]`）、Plausible Analytics、Vercel CDN/Edge
- **不接**：訂房 / 訂票 / 支付（PRD §Non-Goals）

### 上游 PRD 摘要

- **G1**：3 分鐘內生出含建議換匯額的行程，誤差 < 15%
- **P0-8（關鍵缺口）**：接入即時匯率取代模擬值
- **P0-9（關鍵缺口）**：基本使用分析
- **Non-Goals**：不做帳號、不做訂房、不做多人分帳

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`，並先跑完 [`03-prd/`](../../02-define/03-prd/) + [`05-adr/`](../05-adr/) 拿到上游輸出
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（4 個小節：Codebase 結構 / 既有 ADR / Stakeholder / 上游 PRD 摘要，換成你自己的對應內容）
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
