## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **七象限必填**：endpoint + schema + auth + error（含 4xx/5xx）+ idempotency + rate limit + governance。任一象限沒列要在輸出裡說明為何不適用。
- **5xx 至少要分 502（依賴失效）與 500（自家 bug）**。FE 無法靠單一 500 判斷該 retry 還是該切 fallback；error code 設計是 UX 決策的延伸。
- **§Governance 段的 change policy 必須寫死**：版本策略（如 `/api/v1/`、sunset header）、deprecation 通知期、consumer 通知機制。沒寫 = breaking change 來時整條 chain 全炸。
- **每個 schema 都要帶 `example`**，且 enum / pattern 要有約束。OpenAPI 機械可消費的前提是 example 存在，FE mock server 才能跑。
- **法規欄位（如 disclaimer）放進 response schema、不要寫死在 client**。法務改文案不該需要重新部署。
- **Rate limit 數字不能憑空抄「100 req/min」**，要附「為何此值」（流量估算或標 Open Question）。
- **沒後端 ≠ 不寫 API spec**：只要有跨網路邊界呼叫（如本案 FX proxy + analytics endpoint），就要 freeze 契約。

### SRS / 功能規格

SmartTrip FX 是無自有後端的 SPA，但 C4 卡（06）拆出兩個 server-side 端點：

1. **FX Rate Proxy** — 代理 FX provider、隱藏 API key、5 分鐘快取（對應 PRD P0-5、P0-8）
2. **Analytics Event Collector** — 接收前端事件，目前直接打到 Plausible，未來可能改為 server-side proxy 以便加 enrichment（對應 PRD P0-9）

本卡只契約化這兩個 endpoint。所有「業務邏輯」（三方案計算、建議換匯、燈號）都在前端 lib/ 完成，不走 API。

### User story / 使用情境

- 旅客打開 /result 頁 → 前端呼叫 `GET /api/fx/rate?base=TWD&quote=JPY` → 拿到今日匯率 + MA30 → 算燈號
- 旅客按「生成行程」→ 前端打 `POST /api/analytics/event` 記 generate 事件
- FX 失敗時：前端顯示「目前匯率資料暫時不可用，已顯示模擬值」（呼應 PRD P0-8 驗收標準）

### 既有 API 風格指南 / error taxonomy / auth 模型

- 全 HTTPS only（Vercel 預設）
- 無使用者帳號 → 無 user auth；FX endpoint 為公開讀取（但有 IP rate limit）
- FX provider API key 為**服務端 secret**，存 Vercel env var
- Error 採 RFC 7807 Problem Details JSON 格式（`{ type, title, status, detail, code }`）
- 版本前綴 `/api/v1/`（即使是 MVP 也預留版本欄位）

### 上游卡輸出（C4 Level 2 摘要）

- Container C-2 `FX Rate Proxy`：Next.js Route Handler，Node runtime
- 對外暴露：`GET /api/fx/rate`、`POST /api/analytics/event`
- 不暴露：localStorage 操作（純前端）、Trip / Expense 的 CRUD（無後端持久層）

### 上游卡輸出（PRD 摘要）

- G1：3 分鐘完成生成 → API p95 < 500ms（讓 client 計算 + 渲染留 2.5min 緩衝）
- P0-8 驗收：失敗時明確標示「模擬」
- 法規：FX 燈號需「非投資理財建議」免責聲明 → 在 response 加 `disclaimer` 欄位

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`，並跑完 [`03-prd/`](../../02-define/03-prd/模板輸入.md) + [`06-c4-diagram/`](../06-c4-diagram/模板輸入.md) 拿到上游輸出（特別是 C4 Level 2 的 container 列表）
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（把 SRS / User story / API 風格指南 / C4 摘要 / PRD 摘要 5 個小節換成你自己的對應內容）
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
