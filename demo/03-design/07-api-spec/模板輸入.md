## 輸入素材

### SRS / 功能規格（含 endpoint 對應的業務動作）

SmartTrip FX 是無自有後端的 SPA，但 C4 卡（06）拆出兩個 server-side 端點：

1. **FX Rate Proxy** — 代理 FX provider、隱藏 API key、5 分鐘快取（對應 PRD P0-5、P0-8）
2. **Analytics Event Collector** — 接收前端事件，目前直接打到 Plausible，未來可能改為 server-side proxy 以便加 enrichment（對應 PRD P0-9）

本卡只契約化這兩個 endpoint。所有「業務邏輯」（三方案計算、建議換匯、燈號）都在前端 lib/ 完成，不走 API。

### User story / 使用情境（含主要 / 例外流程）

- 旅客打開 /result 頁 → 前端呼叫 GET /api/fx/rate?base=TWD&quote=JPY → 拿到今日匯率 + MA30 → 算燈號
- 旅客按「生成行程」→ 前端打 POST /api/analytics/event 記 generate 事件
- FX 失敗時：前端顯示「目前匯率資料暫時不可用，已顯示模擬值」（呼應 PRD P0-8 驗收標準）

### 既有 API 風格指南 / error taxonomy / auth 模型

- 全 HTTPS only（Vercel 預設）
- 無使用者帳號 → 無 user auth；FX endpoint 為公開讀取（但有 IP rate limit）
- FX provider API key 為**服務端 secret**，存 Vercel env var
- Error 採 RFC 7807 Problem Details JSON 格式（`{ type, title, status, detail, code }`）
- 版本前綴 `/api/v1/`（即使是 MVP 也預留版本欄位）

### 上游卡輸出（C4 Level 2 摘要）

- Container C-2 `FX Rate Proxy`：Next.js Route Handler，Node runtime
- 對外暴露：`GET /api/fx/rate`、`POST /api/analytics/event`
- 不暴露：localStorage 操作（純前端）、Trip / Expense 的 CRUD（無後端持久層）

### 上游卡輸出（PRD 摘要）

- G1：3 分鐘完成生成 → API p95 < 500ms（讓 client 計算 + 渲染留 2.5min 緩衝）
- P0-8 驗收：失敗時明確標示「模擬」
- 法規：FX 燈號需「非投資理財建議」免責聲明 → 在 response 加 `disclaimer` 欄位

## 規則

1. 每個 endpoint / schema 註明 source：[input 第 X 段]；無法歸因者標 [來源未明示，需確認]。
2. Trade-off 必須列負面後果（例：選 sync 回應則犧牲峰值容量；選 async webhook 則增加 FE 整合複雜度）。
3. 缺資料的欄位標 TODO(缺什麼)，不要編造欄位或 error code。
4. 必填涵蓋：endpoint + schema + auth + error（含 4xx/5xx）+ idempotency + rate limit + governance；任一象限沒列要說明為何不適用。
5. Out of scope 至少 3 條（例：內部 RPC、admin console、batch ETL 不在本契約）。
6. 每個關鍵宣稱標 confidence: [H/M/L]，L 必須附說明。
7. Breaking change policy 必須寫死（版本策略 / deprecation 通知期 / consumer 通知機制）。
