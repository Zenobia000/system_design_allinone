```yaml
endpoints:
  - path: /api/v1/fx/rate
    method: GET
    operationId: getFxRate
    summary: 取得今日匯率與 MA30，用於 FX 燈號計算
    auth_scope: ["public"]  # 無 user auth；server-side 持有 FX provider API key
    idempotency_key: n/a   # GET 本質冪等
    rate_limit: 60 req/min per IP（含 5-min 快取後實際打 FX provider 的 QPS 遠低於此）
    source: [PRD P0-5, P0-8, C4 卡 C-2]
    confidence: H

  - path: /api/v1/analytics/event
    method: POST
    operationId: postAnalyticsEvent
    summary: 接收前端事件並轉送 Plausible（保留未來加 server-side enrichment 空間）
    auth_scope: ["public"]
    idempotency_key: optional  # 客戶端可帶 Idempotency-Key 避免網路重試重複計數
    rate_limit: 120 req/min per IP（單一使用者一次 session 約 5-15 事件，留 8x 餘裕）

    confidence: M  # 是否 server-side proxy vs client 直打 Plausible 待 ADR-004 sign-off

  GetFxRateQuery:
    type: object
    required: [base, quote]
    properties:
      base:
        type: string
        pattern: '^[A-Z]{3}$'

        description: ISO 4217 三字母幣別（旅客本國幣別）
      quote:

        pattern: '^[A-Z]{3}$'

    required: [event_name, occurred_at]
    properties:
      event_name:
        type: string
        enum: [generate, tier_select, save_trip, add_expense, deal_link_click, return_visit]
        example: "generate"
        description: 對應 PRD §8 量測事件清單
      occurred_at:

        example: "2025-05-26T08:30:00Z"
      session_id:
        type: string
```

## 教學要點（看完 AI 輸出後讀這段）

### 1. 為什麼 SmartTrip FX 這個「純前端 SPA」也要寫 API spec？

brief 主要約束說「MVP 用 localStorage、不做後端」，學生常誤以為「沒有 API 就不用寫 API spec」。但 C4 卡（06）拆出兩個 server-side endpoint：FX Rate Proxy（避免 API key 外洩）、Analytics Event（保留 server-side enrichment 空間）。

**只要有「跨網路邊界的呼叫」就要 freeze 契約**。否則 FE 寫 fetch、BE 寫 handler 各自想像，整合那一刻全部對不上。

### 2. 為什麼 5xx 要拆 500 vs 502？

`decision_log` 第二條寫得很清楚：**FE 無法判斷該 retry 還是該切 simulated**。

- 502 (FX_PROVIDER_UNAVAILABLE) → FE 切 simulated 模式（PRD P0-8 驗收）
- 500 (INTERNAL_ERROR) → 自家 bug，可 retry

學生若把所有 5xx 都用 500 統包，前端就只能盲 retry，違反 PRD「失敗時明確標示模擬」的驗收條件。**Error code 設計是 UX 決策的延伸**。

### 3. `disclaimer` 欄位為什麼是 required？

brief 的「主要約束」明示：**FX 燈號需「非投資理財建議」免責聲明**。

把 disclaimer 放在 server response 而非寫死在 client，好處：

- 法務想改文案不用改 code 重新部署
- 跨 client（未來 V1 App）共用同一份免責文字
- Contract test 可驗證每次回應都帶 disclaimer

學生常把法規欄位視為「UI 文案」而忘了寫進 API schema，等於把法規風險留在 client。

### 4. 這張卡的輸出流向下游哪些卡

| 本卡欄位 | 流向哪張卡 |
|---|---|
| `endpoints[]` + `rate_limits` | `09-non-functional-reqs/` latency_targets + scalability |
| `error_taxonomy` | `10-code-review-checklist/` error handling 維度 |
| `component_schemas.FxRateResponse` | `08-data-model/` FXRateCache entity 欄位對應 |
| `x_governance.freeze_date` | 專案時程 / `05-adr/` ADR-XXX |
| `decision_log` REST vs GraphQL | `05-adr/` 補 ADR-006 API 風格 |

## 學生常見錯誤（交件前自己對照）

| 錯誤 | 違反規則 | 怎麼修 |
|---|---|---|
| 只寫 200 response，沒寫 4xx/5xx | 規則 4（必填涵蓋 error） | 至少列 400 / 429 / 5xx；每個都用 RFC 7807 ProblemDetails |
| 沒寫 `x_governance.change_policy` | 規則 7（breaking change policy） | 必須寫死版本策略 + deprecation 通知期 |
| `auth_scope` 全寫 `[]` 或漏寫 | 規則 4 | 即使是 public 也要明寫 `["public"]` + 在 auth_scopes 解釋為何無 user auth |
| Rate limit 直接抄「100 req/min」沒解釋 | 規則 3（不要抄業界） | 必須附「為何此值」（含 traffic 估算或 PRD Open Question 標註） |
| schema 沒給 `example` | OpenAPI 機械可消費要求 | 每個 schema 至少一個 example，FE mock server 才能用 |

## 交件 checklist

- [ ] 每個 endpoint 都寫齊 path + method + operationId + auth_scope + rate_limit
- [ ] Response 涵蓋 2xx + 4xx + 5xx，且 5xx 至少區分 502（依賴失效）與 500（自家 bug）
- [ ] 所有 error code 收錄在 `error_taxonomy`，並標 retryable + user_message_key
- [ ] `idempotency_keys` 對所有非冪等動作（POST/PATCH/DELETE）明寫 required/optional/n/a
- [ ] `x_governance.change_policy` 寫死 breaking / non_breaking 流程
- [ ] `out_of_scope` 至少 3 條
- [ ] 每個 `confidence: M/L` 對應一條 `self_review.lowest_confidence` 補洞計畫
- [ ] schema 都帶 `example`，且 enum / pattern 有約束
