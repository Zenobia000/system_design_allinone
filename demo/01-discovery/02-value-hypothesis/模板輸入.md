## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **Riskiest assumption 不是「最大」風險，而是「錯了就殺死整個 idea」的那條**。學生最常把「最焦慮的技術問題」當 riskiest，那是 feasibility 不是 desirability。
- **`Test Method` 成本必須 < 1 週且優先 no-code / smoke_test**。超過就要在 Decision Log 表的 Rejected why 欄解釋為何。
- **`Kill Criteria` 必須真的可被觸發**，不能寫「不達標就再優化」這種留逃生口的句式。容忍下限通常設目標的 50–60%。
- **`Success Threshold` 的 baseline 沒資料就誠實標 `_TODO: 從首兩週實測校準_` + `[L]` confidence**，不要把 brief 拍腦袋的目標數字當既定真理。
- **本卡的 §Out of Scope 是「文件 scope」**（不畫 UI / 不寫實作 / 不定價），不是「產品 non-goal」（後者屬 PRD）。別混淆。

### 模糊 idea / 老闆說要做的功能描述

SmartTrip FX 一句話定位：「唯一會幫你算『該帶多少外幣現金、何時換最划算』的個人旅遊小工具」。
我們相信「先算錢」這個切角是差異化護城河，但目前沒有任何外部證據，純屬團隊內部信念。
本卡要驗證的不是某個功能，而是**整個 MVP 的定位假設是否成立**：4 週驗證窗結束時，我們敢不敢繼續做 V1。

### 目標受眾

25–40 歲台灣衝動型出境旅客，一年 1–4 趟、以日韓泰為主、預算敏感、習慣帶現金、決策快怕麻煩。次要族群：第一次自由行的新手。

### 待解痛點（brief §痛點）

不知道該帶多少外幣現金、哪些地方只收現金、現在換匯划不划算。換太多 → 回國再換虧匯差；換太少 → 現場狼狽。在一趟 NT$40,000 的旅程中，匯損與多換的成本可達數百到上千元。現有行程規劃工具與 OTA 完全不處理這件事，旅客只能憑感覺換匯。

### JTBD 卡（取自上游 01-jtbd 實際結果，列出與本卡最相關的兩條）

- **JTBD-001**：When 我下週要出國但不知道帶多少外幣現金, I want to 一鍵算出該換多少 + 看到換匯時機燈號, so I can 不換太多虧匯差也不會當場狼狽。
  - success_criteria: ≤ 3 分鐘完成估算 / 現金誤差 < 15% / 不需要切換 3 個工具
  - opportunity_size: 1–4 次/年/人，P1 + P2
- **JTBD-003**：When 我想出國但選擇困難時, I want to 用心情 + 預算範圍快速生出三種行程選項, so I can 不用花一週爬文就能拍板。
  - success_criteria: 3 方案皆 ≤ 預算上限 / 心情/主題對得起來

### 現有 metric baseline（conversion / retention / activation）

⚠️ **本專案無任何 baseline**：產品 v0.1 剛上線，未接入分析工具。
所以下列假設的 baseline 必須誠實標 `[L]` confidence 並標 `_TODO: 從首兩週實測校準_`。

### 主要約束

- 不做帳號雲端同步（MVP 用 localStorage）
- 不做訂房比價（外部連結導出）
- **4 週 MVP 驗證窗** ← 本卡的決策時間盒
- FX 燈號需「非投資理財建議」免責聲明

### 預設成功指標（要驗證、不是要照抄）

- 啟用率 ≥ 40%
- 存檔率 ≥ 25%
- 30 天回訪 ≥ 20%
- 換匯誤差 < 15% 的行程比例 ≥ 60%

⚠️ 這些數字是團隊拍腦袋，**沒有 baseline 校準**。本卡要把它們轉成可被殺的 kill criteria，而非當作既定目標。

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`，並先跑完 [`01-jtbd/`](../01-jtbd/) 拿到 JTBD 輸出
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（把模糊 idea / 目標受眾 / 待解痛點 / JTBD 卡 / metric baseline / 主要約束 / 預設成功指標 7 個小節換成你自己 brief + JTBD 卡的對應內容）
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
