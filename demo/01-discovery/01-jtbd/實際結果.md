# 01-JTBD · 實際結果（AI 回的內容 + 教學要點）

> **這個檔案的用途**：把 [`模板輸入.md`](./模板輸入.md) 完整 prompt 段貼到 Claude 後，AI 真的回的內容。
> 你自己跑出來的結果不會完全一樣（AI 有變異性），但**結構、規則、confidence 標註方式**應該對得起來。
> 對照重點看下方的「**教學要點**」與「**常見錯誤**」。

## 教學要點（看完 AI 輸出後讀這段）

### 1. 為什麼 JTBD-001 的 `functional_job` 標 H、`social_job` 標 L？

`functional_job` 直接對應輸入需求的「待解痛點」與「期望成果」兩段，有兩處來源互相印證 → H。
`social_job` 沒有任何 input 提到「在他人面前的形象」，純屬 AI 推論。誠實標 L，**學生別美化成 M**。

### 2. 為什麼 JTBD-005 整張卡 confidence 都是 L 還要留？

`decision_log` 寫得很清楚：**留它做訪談題引導**。
若全砍掉，後續訪談時不會有人主動聊到社交動機，差異化驗證就少一條路徑。
這是「保留低 confidence 但有策略價值的 JTBD」的典型決策，**學生產出時要把這層 trade-off 顯式寫進 decision_log**，不能默默留下。

### 3. `mutually_exclusive_jobs` 為什麼重要？

兩組互斥都對應到 brief 裡的真實取捨：

| 互斥組 | 對應到輸入需求哪一條 |
|---|---|
| JTBD-002 vs JTBD-003 | 主要約束 - 不做帳號雲端同步 |
| JTBD-001 vs JTBD-005 | 期望成果 - 3 分鐘完成 |

學生若沒寫 `mutually_exclusive_jobs`，下游 PRD/AC 會把所有 JTBD 等價對待，做出來的功能會互相打架。

### 4. 這張卡的輸出流向下游哪些卡

| 本卡欄位 | 流向哪張卡 | 為何 |
|---|---|---|
| `JTBD-001.success_criteria` 的「≤ 3 分鐘」「誤差 < 15%」 | [`02-value-hypothesis`](../02-value-hypothesis/) 期望成果、[`03-prd`](../../02-define/03-prd/) Goal G1 | 把 JTBD 的 success_criteria 翻成可驗證假設與 PRD goal |
| `mutually_exclusive_jobs` JTBD-001 vs JTBD-005 | [`09-non-functional-reqs`](../../03-design/09-non-functional-reqs/) 效能 NFR | 互斥要在 NFR latency 設計時當取捨依據 |
| `out_of_scope` 第 3 條（KPI 公式） | [`02-value-hypothesis`](../02-value-hypothesis/) 與 [`03-prd`](../../02-define/03-prd/) 的指標公式 | 本卡明確說不寫公式，下游負責 |
| `self_review.highest_value_next_input` | 下次 user-research 計畫 | 不是下游卡，但提示下一輪訪談優先級 |

## 學生常見錯誤（交件前自己對照）

| 錯誤 | 違反規則 | 怎麼修 |
|---|---|---|
| 把功能寫成 JTBD：`When 出國時 I want to 一個按鈕讓我看到匯率` | 規則 4 | `I want to` 後面寫**動機**，不寫**操作**（按鈕、頁面、API） |
| 直接列 5 個 JTBD 但不寫 `decision_log` | 規則 5 暗示 | 至少寫一條：為什麼是這 5 個、捨棄了哪些 |
| `confidence` 全標 H | 規則 6 | 沒有訪談原句就標 M/L，並在 `self_review` 寫補洞計畫 |
| `out_of_scope` 寫成空陣列或漏掉 | 規則 5 | 至少 3 條：不排功能優先序、不寫實作、不定義 KPI 公式 |
| 只寫 `functional_job`，省略 `emotional/social` | 規則 7 | 三層至少都要寫到 `functional + emotional`，social 沒證據時誠實標 L |

## 交件 checklist

- [ ] 每個 JTBD 都寫成 `When ... I want to ... so I can ...` 三段
- [ ] 沒有出現「按鈕/頁面/API」這類解法字眼
- [ ] 至少有一組 `mutually_exclusive_jobs` 並說明 tension
- [ ] `decision_log` 至少一條，列出 `options_considered` + `rejected_reason`
- [ ] `out_of_scope` 至少 3 條
- [ ] 每個 `confidence: L` 都在 `self_review.lowest_confidence` 對應一條補洞計畫
- [ ] `functional / emotional / social` 三層至少寫到 functional + emotional
