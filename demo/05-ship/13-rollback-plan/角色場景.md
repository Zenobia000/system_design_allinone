# 13 Rollback Plan · 角色場景

## 這場會議在做什麼

12-release-plan 把「要上什麼、什麼時間、誰按按鈕」談完了。
這場 45 分鐘的 **rollback 預演會** 是上線**前**的最後一道閘門：
針對每一個將要上線的**不可逆變更**（schema migration、外部 vendor 切換、PWA service worker 版本切換），
逐一回答「**萬一爆了，rollback button 真的能按嗎？按下去之後使用者會看到什麼？**」

**不是**做 release plan（那是 12-release-plan）、**不是**寫 on-call runbook（那是 14-runbook）、**不是**做事後檢討（那是 15-postmortem）。
這場只做一件事：**把每一條 release 變更，配一條已驗證過的 rollback path**。
配不出來就**不准進這波 release**——退回 12-release-plan 重切批次。

## 誰在場

| 角色 | 帶來什麼 | 想拿走什麼 |
|---|---|---|
| **DevOps（主責，你）** | release 變更清單、部署拓樸、過往 incident log、可逆性矩陣 | 每條變更對應 1 條 rollback path + 演練紀錄 |
| **PO** | 商業影響底線（rollback 後使用者體驗能掉到多差還可接受） | 對外通訊腳本、客服回覆模板 |
| **Dev** | code change、feature flag、schema diff、相容性說明 | 自己要寫 / 改 / 演練哪些 rollback 程式碼 |

## 你扮演的角色（DevOps）

你是「**rollback button 必須能按**」的守門員。本場會議你只做兩件事：

1. 每一條 release 變更，問 Dev「**這個變更可逆嗎？不可逆的話前向／向後相容怎麼處理？**」
   不可逆 + 沒相容方案 → **直接 block this release**，不接受「應該不會出事」。
2. 每一條宣稱「可 rollback」的方案，問 Dev／自己「**上次實際演練是什麼時候？演練紀錄在哪？**」
   沒演練過 = 沒有 rollback path，只是文件裡的字。當場排演練時段。

**禁忌動作**：本場會議不能講「**rollback 就好**」「**到時候再看**」「**應該不會發生**」這三句話。
一講就罰自己 100 元——這三句話翻譯成事實是「我沒想過 rollback 的細節」「我把問題丟給未來凌晨 3 點的自己」。

## 會議結束時，桌上要有什麼

- 一張 **rollback 矩陣**，每一條 release 變更一列，欄位含：
  - trigger signal（什麼信號觸發 rollback，自動 vs 人工判定）
  - rollback steps（具體可執行步驟，含指令／按鈕／聯絡人）
  - data compatibility（schema 變更如何處理：dual-write / feature flag / backfill / 不可逆+補償）
  - user impact（rollback 後使用者看到什麼，舊資料能讀嗎，會被踢回舊版嗎）
  - 通訊鏈條（誰通知誰、客服 FAQ、status page 文案、對 PO/老闆的 escalation）
- 至少 3 個 **rollback 場景**已**實際演練過**（含演練時戳、執行人、發現的問題）
- 一張「**不可 rollback 的變更清單**」+ 對應補償方案（forward fix 路徑、緩解策略、預估復原時間）
- 演練週期排定（建議每 quarter 至少 1 次 game day）
- Decision log：哪些變更被打回 12-release-plan 重切批次、為什麼

## 為什麼這場會議重要

Release 不是「按下按鈕的瞬間」，而是「按下按鈕**之後到下次安全狀態**的整段時間窗」。
這個時間窗裡 rollback button 能不能按，決定了：

- **14-runbook** 凌晨 3 點被 page 的人，第一步是不是「按 rollback」（明確 → 快速復原；模糊 → 不敢按 → 拖延）
- **15-postmortem** 的 mitigation time，是 3 分鐘還是 3 小時（差別在 rollback path 是否已演練）
- **09-NFR** 承諾的 SLO（譬如「p95 < 180s」）能不能在事故時止血回到 SLO 內
- **04-AC** 在 release 後第一個小時的監控門檻——掉到哪條線觸發自動 rollback

跳過這場會議的代價：**所有 release 變更都成了「希望它不要爆」的賭博**。
SmartTrip 雖然 MVP 用 PWA + localStorage 沒有 server 部署，
但 **FX rate API provider 切換** 與 **PWA service worker 版本切換** 這兩個變更一旦做錯，
使用者裝在手機上的 PWA 會被卡在錯誤版本，沒有 rollback 演練就只能眼睜睜看 1,200 個行程算錯錢。
