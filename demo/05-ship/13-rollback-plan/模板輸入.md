## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **`Triggers` 編號必須對齊 12-release-plan 的 `Abort Criteria`**（TRIGGER-1/2/3 一一對應）。編號錯一個，oncall 凌晨 3 點就走錯流程。
- **每個 `Rollback Steps` 的 command 必須可直接複製貼上執行**。不可寫「redeploy previous」這種需要查文件才能跑的句子；要寫 `vercel rollback --token=$VERCEL_TOKEN` 這種完整指令，並且最好同時附 CLI + UI fallback。
- **每個 step 必須有 `verification` 欄位**（如 `curl -I ... | grep ...`），證明這步真的執行成功。沒有驗證 = 沒做過。
- **不可逆 migration（forward-only）必須標 `reversible: false` 並寫補救方案**。只標旗號不寫怎麼救，下次真的 rollback 時 oncall 會誤清 localStorage 弄丟使用者資料。
- **`MTTR target` 必須是具體分鐘數**，不可寫「越快越好」。個人 MVP 15 分鐘是合理上限。

### Deploy steps（Vercel）

```
1. git push origin main → Vercel auto-deploy production
2. Vercel build (約 2 分鐘) → 產生新 deployment URL
3. Vercel 自動把 production alias (smarttrip-fx.vercel.app) 指向新 deployment
4. 上線完成
```

### Migration scripts

PR #45 的 `migrate()` 函式：

```typescript
// src/lib/storage/migrate.ts
function migrate(stored: unknown): TripStorageV1 {
  if (!stored) return { version: 1, trips: [] };
  if (isV0(stored)) {
    // V0 -> V1: 加 version 欄位、把 expense.amount 從 number 改為 { value, currency }
    return { version: 1, trips: stored.trips.map(upgradeTrip) };
  }
  return stored as TripStorageV1;
}
```

**注意**：V0 → V1 後，舊版 SmartTrip FX (v0.1.x) 讀不回 V1 schema（無 backward read）。

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**：
   - 把上游 `12-release-plan/實際結果.md` 的 `Abort Criteria` 整段貼到「對應 release plan」（編號必須跟上游一致）
   - 把「Deploy steps」換成你的部署流程（不是 Vercel 就改成你自己的 CI/CD 步驟）
   - 把「Migration scripts」換成你的 schema 變更（沒有的話誠實寫「無 schema 變更」並省略 Inverse Migrations 段）
   - 把「SLO 與業務指標」對齊你 brief 的「成功指標」段
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
