## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **`Go/No-Go` 段的 decision_maker 必須是具體角色或人**。不能寫「團隊」「待定」；個人專案就誠實寫「我自己」，讓 go/no-go 有人扛責任。
- **`go_criteria` / `success_criteria` / `abort_criteria` 三者不能混為一談**。前者上線**前**判斷按不按、中者上線**後** 24h~7d 判定成功、後者上線**後** 30min~1h 判定失敗觸發 rollback，下游 SRE 才知道何時看哪一條。
- **`Post-release Metrics → Abort Criteria` 必須引用 13-rollback-plan 的 TRIGGER 編號**（如 TRIGGER-1/2/3）。只寫「失敗率高就 rollback」會讓 oncall 還要重新判斷。
- **`Comms Plan` 必須含 internal / external / support 三層**。個人專案無正式 support 也要誠實寫 `_TODO: 填上 oncall_`，不可省略。
- **`Rollback link` 不可為 TODO**。release plan 沒退路就不該按 deploy。

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**：
   - 把「本次 release scope」換成你自己的 PR 清單（`git log v0.1.0..HEAD --oneline` 抓出來）
   - 把「服務依賴圖」換成你自己的 upstream / downstream（沒有就誠實寫「無正式 consumer」）
   - 把「專案脈絡」對齊你 brief 的「目標受眾 + 主要約束」段
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md) 的「教學要點」與「常見錯誤」

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
