## ⚠️ 本卡注意事項（進 Claude 前先讀）

- **F.I.R.S.T 原則是底線**。Fast / Independent / Repeatable / Self-validating / Timely — 任一違反就是壞測試。`expect(r).toBeDefined()` 違反 Self-validating，必須用具體 expected value。
- **6 類 case 至少涵蓋 4 類**：happy / boundary / error / null_empty / concurrency（若 stateful）/ idempotency（若有副作用）。只測 happy path 是新手最常見的錯。
- **mutation_kill 比 line coverage 更有意義**。line 95% 只證明「跑到」，mutation_kill 70% 才證明「測試在檢查邏輯」。target 設 mutation_kill 比死盯 line% 有用。
- **同 module 內的 pure function 不該 mock**。§Mocking Strategy 段 `do_not_mock` 必須明列 — mock 進位函式 = 測 mock 而非業務規則，違反 Self-validating。
- **spec 沒寫的邊界（負數 / null / 跨幣別混合）誠實標 `[L]` confidence 並回退補 spec**。不要編一個錯誤訊息文案進去填補空白。

### 函數簽名（TypeScript）

```typescript
// src/lib/fx/cash-suggestion.ts
type ItineraryItem = {
  id: string;
  title: string;
  estimatedCost: number;        // 該項花費（單位由 currency 決定）
  currency: 'JPY' | 'KRW' | 'THB' | 'USD' | 'TWD';
  paymentType: 'cash_only' | 'card_ok' | 'either';
};

type CashSuggestion = {
  currency: string;
  amount: number;               // 已加 10% 緩衝 + 進位後的建議換匯額
  twdApprox: number;            // 台幣約當
  breakdown: { cashOnlySum: number; bufferRate: number };
};

export function suggestCashAmount(
  items: ItineraryItem[],
  targetCurrency: 'JPY' | 'KRW' | 'THB' | 'USD',
  fxRateToTWD: number,
): CashSuggestion;
```

### 功能規格（來自 PRD P0-4 + 期望成果）

- **規則**：建議換匯額 = `sum(items where paymentType === 'cash_only' AND currency === targetCurrency).estimatedCost` × 1.1
- **進位規則（依幣別）**：
  - JPY：無小數，向上進位到 100 日圓（例：12345 → 12400）
  - KRW：無小數，向上進位到 1000 韓元
  - THB：保留 2 位小數，向上進位
  - USD：保留 2 位小數，向上進位
- **acceptance criteria（PRD P0-4）**：顯示金額、台幣約當、緩衝說明；數字與規則一致
- **期望成果**：事後實際現金花費與建議值誤差 < 15%
- **法規約束**：FX 燈號需「非投資理財建議」免責聲明（本函式不負責顯示，但測試需確認回傳結構不假裝是金融建議）

## 替換成自己專案的方法

如果你不是要做 SmartTrip FX：

1. 跑 [`/start/`](http://localhost:3000/start/) 問卷 → 下載你自己的 `project-brief.md`，並從 PR 抓出要測的函式（或從 [`03-prd`](../../02-define/03-prd/模板輸入.md) 的 P0 需求推導）+ [`04-acceptance-criteria`](../../02-define/04-acceptance-criteria/模板輸入.md) 對應 AC + CI 跑出的真實 coverage（沒跑過就標 TODO）
2. 步驟 1（複製站上「完整範本」tab）**完全不動**
3. 步驟 2 的 trigger 結構不動；**只替換 `⏫` 上方的「上游文件」貼位區**（把函數簽名 / 功能規格 / 既有測試 + coverage 3 個小節換成你自己的對應內容）
4. 貼到 Claude → 對比你拿到的結果與 [`實際結果.md`](./實際結果.md)

> **為什麼步驟 1 不動？** 因為站上模板就是 single source of truth。版本升級（規則修訂、章節增刪）會自動同步到所有學生的下次產出，不需要去改舊的 demo 檔。
