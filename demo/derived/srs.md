## 1. Executive Summary

把 PRD 的「使用者要什麼」翻成「系統要做什麼」。範圍限定 **SmartTrip FX MVP**：一個 **PWA，無後端使用者資料庫，資料存 localStorage**。

系統邊界的三句話：

1. **系統不持有使用者資料**。所有行程與開支存在瀏覽器，伺服器端只有靜態資源與 FX 代理。
2. **系統唯一的外部依賴是匯率**。FX 來源不可用時系統必須降級而非失敗（PRD P0-8）。
3. **系統不做身分識別**。無帳號、無 session、無 cookie 追蹤（種子簡報「免登入、重隱私」）。

> 這三條同時是**架構約束**與**驗收依據**。任何違反其一的實作提案，需走 `adr` 重新決策。

## 2. Use Cases

| ID | Use Case | Actor | 前置條件 | 主要流程 | 後置條件 | 對應 PRD |
|---|---|---|---|---|---|---|
| **UC-01** | 生成行程與換匯建議 | 旅客 | 無（免登入） | 1. 輸入目的地／日期／幣別／預算／心情 2. 系統驗證必填 3. 取得匯率 4. 計算三級距 5. 計算建議換匯額 6. 回傳結果 | 畫面顯示 Low/Mid/High 三方案，各含總花費與建議換匯額 | P0-1、P0-2、P0-4 |
| **UC-02** | 檢視行程時間軸 | 旅客 | UC-01 完成 | 展開任一級距 → 顯示逐項行程，每項標註現金／刷卡與預估金額 | 使用者可判斷哪幾天需要現金 | P0-3 |
| **UC-03** | 檢視換匯燈號 | 旅客 | UC-01 完成、FX 資料可用 | 顯示今日匯率、MA30、偏離百分比、燈號（STRONG_BUY／BUY／HOLD） | 使用者得到「現在換划不划算」的判斷依據 | P0-5 |
| **UC-04** | 儲存行程 | 旅客 | UC-01 完成 | 按「儲存此行程」→ 寫入 localStorage | 「我的行程」可見；重整不消失 | P0-6 |
| **UC-05** | 記錄開支並對比預算 | 旅客 | UC-04 完成 | 新增／刪除開支（現金／刷卡）→ 即時更新總額與超支／結餘 | 使用者知道有沒有超支 | P0-7 |
| **UC-06** | 匯率降級運作 | 系統 | FX 來源異常 | 1. 主來源逾時／5xx 2. 切換備援 3. 兩者皆失敗 → 使用 cached 值並標示 4. 無 cache → 隱藏燈號、保留建議換匯額 | 使用者看到明確的資料狀態標示，核心流程不中斷 | **P0-8** |
| **UC-07** | 記錄使用行為 | 系統 | 使用者未拒絕分析 | 於 generate／tier_select／save_trip／add_expense／deal_link_click／return_visit 發送匿名事件 | PM 可判定 `okr` KR1／KR2 | **P0-9** |

### 用例關係

```
UC-01 ──┬── UC-02

        └── UC-04 ── UC-05
UC-07 橫切所有用例（觀測，不改變主流程）
```

## 6. External Interfaces

### 6.1 外部系統

| # | 介面 | 方向 | 協定 | 用途 | 失效影響 |
|---|---|---|---|---|---|
| **EI-1** | FX 匯率主來源 | 出 | HTTPS / JSON | 取得今日匯率與歷史值（算 MA30） | UC-03 降級；UC-01 仍可運作 |
| **EI-2** | FX 匯率備援來源 | 出 | HTTPS / JSON | 主來源失效時接手 | 兩者皆失效 → UC-06 走 cached |
| **EI-3** | 分析服務 | 出 | HTTPS / beacon | 送匿名事件（UC-07） | **不得影響主流程**；失敗即丟棄 |
| **EI-4** | 外部訂票／訂房站 | 出 | 連結導出 | PRD P1 搜尋連結 | 連結失效僅影響 P1 |
| **EI-5** | Feature flag 服務 | 出 | HTTPS / SDK | 燈號開關、來源切換（UC-06） | 失效時採用內建預設值 |

> **EI-1／EI-2 的具體供應商未定**（PRD §9 阻擋項）。本規格只約束**介面形狀**，不綁定供應商：
> 任一來源必須能提供 `{ base, quote, rate, asOf }` 與可回推 30 個交易日的歷史序列。

### 6.2 使用者介面

| 需求 | 規格 | 來源 |
|---|---|---|
| 裝置 | 行動優先，iOS Safari／Android Chrome 最近兩個大版本 | `persona` 小美用 iPhone |
| 離線 | 已存行程須可離線開啟（service worker 快取） | `persona`「出國訊號不穩」 |
| 首個有用輸出 | 進站 → 建議換匯額顯示，中位數 < 3 分鐘 | PRD §7；`journey-map` MoT-1 |
| 語言 | 繁體中文 | 目標市場 |
| 免責 | FX 燈號附「非投資／理財建議」聲明 | 種子簡報 §主要約束（法規） |

### 6.3 資料介面

| 項目 | 規格 |
|---|---|
| 持久化 | `localStorage`，JSON 序列化，不存 Date 物件（`adr` Consequences 要求） |
| Schema 預留 | 每筆行程保留 `userId`（MVP 恆為 null）與 `lastModified` | 
| 容量 | iOS Safari 約 5MB 為設計上限 |
| 匯出 | MVP 不做（PRD P1 分享／匯出屬 Next） |

## 10. Decision Log

| # | 決策 | 理由 | 影響 |
|---|---|---|---|
| D1 | **系統不持有使用者資料**（無後端 DB） | 種子簡報「免登入、不做雲端同步」；`adr` ADR-001 已決 | 大幅簡化 SRS：無認證、無授權、無 GDPR 資料主體流程 |
| D2 | **FX 介面以形狀約束，不綁供應商** | PRD §9 資料源未定，但介面可先鎖 | US-01 可先開發 adapter，不被選型阻塞 |
| D3 | **分析失敗不得影響主流程** | 觀測不能成為單點故障 | 寫入 `error-handling` 與 `observability-spec` |
| D4 | **UC-06 降級須保留建議換匯額** | `persona` Anti-Persona：燈號可關，金額不可失 | P0-4 與 P0-5 解耦，對應 `feature-flag` `fx_signal_show` |
| D5 | **localStorage 5MB 為設計上限**（取較嚴的 iOS） | 避免只在 Android 測而遺漏 | 對應 `runbook` Runbook 02 quota 事故 |
