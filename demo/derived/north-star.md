## 1. Executive Summary

北極星只能有一個。SmartTrip FX 選的是：

> **每週「拿到可信換匯建議並實際採用」的旅客數**
> （Weekly Trusted Currency Plans, **WTCP**）

選它的理由不是它最好量，而是**它同時包含「用了」與「有用」**。PRD §7 列了 8 個指標，但那是一組儀表板，不是北極星——一組指標無法在爭論時裁決優先級。

**警告先寫在前面**：WTCP 目前**無法完整量測**。P0-8（即時匯率）與 P0-9（分析）未上線前，「可信」與「採用」兩個修飾詞都是估的。見 §12。

## 2. North Star Metric

### 定義

```
WTCP = 一週內，滿足下列全部條件的不重複行程數：
  (1) 完成一次 generate           ← 拿到建議
  (2) 觸發 tier_select 或 save_trip ← 表示接受了某個方案
  (3) 該行程的 FX 資料來源標記為「即時」而非「模擬」  ← 建議可信
```

| 項目 | 內容 |
|---|---|
| **單位** | 行程數（不是使用者數，一人可規劃多趟） |
| **週期** | 週（自然週，週一 00:00 UTC+8 起算） |
| **資料來源** | P0-9 分析事件 `generate` / `tier_select` / `save_trip` + FX 來源標記 |
| **驗證窗目標** | 4 週驗證窗結束時 **WTCP ≥ 120／週** `[L]`（見 §12 為何是猜的） |

### 為什麼不是其他候選

| 候選指標 | 為什麼被否決 |
|---|---|
| **DAU / MAU** | 本產品**不該**有高頻使用。小美一年開 3 次就夠了，衝 DAU 會逼團隊做每日簽到這種傷害定位的功能 |
| **生成次數** | 只證明「有人點了按鈕」，不證明有用。反覆生成往往代表**不信任**（`user-research` F4） |
| **存檔率** | 好指標，但只是比例。**比例無法反映規模**，10 人存 3 人和 1000 人存 300 人是同一個數字 |
| **換匯誤差 < 15% 的比例** | 這是**價值證明**（PRD G1），但樣本只含願意記開支的人，偏誤太大，且回收延遲 2–4 週，不適合當週節奏的北極星 |
| **營收** | 驗證期無商業模式（PRD §9 Open Question），無從量測 |

## 3. Leading Indicators

北極星每週才動一次，太慢。下面三個是**可以每天看、且能解釋 WTCP 為什麼變動**的前導指標。

| # | 前導指標 | 定義 | 目標 | 對應 WTCP 的哪一段 | 對應 PRD |
|---|---|---|---|---|---|
| **L1** | **啟用率** | 進站者完成一次 `generate` 的比例 | ≥ **40%**（stretch 55%） | 條件 (1)：有沒有拿到建議 | §7 領先指標 |
| **L2** | **採用率** | `generate` 之後觸發 `tier_select` 或 `save_trip` 的比例 | ≥ **25%** | 條件 (2)：建議有沒有被接受 | §7 存檔率 |
| **L3** | **首個數字時間** | 進站 → 螢幕出現建議換匯額的中位數 | < **3 分鐘** | 條件 (1) 的品質；`journey-map` MoT-1 | §7 完成時間 |

**三者的關係**：`WTCP ≈ 週進站數 × L1 × L2 × (即時匯率覆蓋率)`。
L3 不在乘式裡，但它是 L1 的主要驅動——`journey-map` MoT-1 指出三分鐘內看不到數字就會流失。

## 4. Counter-Metric（防 Goodhart）

北極星會被作弊。下面是**必須同時盯住、否則 WTCP 上升是假的**的反向指標。

| # | 反指標 | 定義 | 紅線 | 防止什麼作弊 |
|---|---|---|---|---|
| **C1** | **換匯建議誤差率** | 有記開支的行程中，\|實際現金 − 建議換匯\| / 建議換匯 | 誤差 < 15% 的比例須 ≥ **60%** | 防「為了拉高採用率，建議值一律往高報」——多換一定夠用，但那是**把成本轉嫁給使用者** |
| **C2** | **重複生成次數／行程** | 同一行程 `generate` 的平均次數 | ≤ **2.5 次** | 防「使用者反覆試」被誤讀為活躍。反覆生成 = 不信任（`user-research` F4） |
| **C3** | **模擬資料曝光率** | 顯示 FX 燈號時資料來源為模擬的比例 | ≤ **5%**（P0-8 上線後） | 防「為了讓燈號永遠有東西顯示，靜默 fallback 到模擬值」——直接摧毀 G4 內容信任 |
| **C4** | **無提示差異化認知** | 訪談／問卷中自發說出「換匯／現金」的比例 | ≥ **60%** | 防「WTCP 上升但使用者其實是來排行程的」——那代表定位失守 |

> **C1 與北極星的張力是刻意的**：把建議值調高 30%，L2 採用率會上升、投訴會下降、WTCP 會漂亮——但 C1 會崩，而 C1 才是 PRD G1 的本體。**任何 WTCP 的改善若伴隨 C1 惡化，一律視為退步。**

## 10. Decision Log

| # | 決策 | 理由 | 影響 |
|---|---|---|---|
| D1 | **北極星選 WTCP 而非啟用率** | 啟用率是比例，無法反映規模；且不含「可信」 | L1 降為前導指標 |
| D2 | **北極星明確排除 DAU** | 高頻使用與產品定位衝突 | 拒絕任何以提升日活為目的的功能提案 |
| D3 | **C1（誤差率）設為一票否決的反指標** | 它是 PRD G1 的本體，也是最容易被犧牲的 | 寫入 `go-no-go-checklist` 與 `error-budget` 的凍結條件 |
| D4 | **WTCP 定義中綁「即時匯率」條件** | 迫使 P0-8 不能被無限延後 | P0-8 未上線前 WTCP 恆為 0，**這是刻意的設計** |
