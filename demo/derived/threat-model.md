## 1. Executive Summary

SmartTrip 的威脅模型與典型 Web 產品**相反**：沒有帳號、沒有後端資料庫、沒有金流，**所以傳統的高價值資產幾乎不存在**。

真正的資產只有一個：

> **使用者對「這個數字可信」的信任。**

因此最高風險的威脅不是資料外洩，是**竄改（Tampering）與否認（Repudiation）**——有人讓燈號顯示錯誤的建議，或我們自己算錯卻無法證明當時算了什麼。這直接對應 `runbook` 04（燈號異常）被列為 SEV-1 的理由。

## 2. Trust Boundaries & Assets

### 信任邊界

```
┌─ 使用者裝置（不可信：使用者可任意修改）────────────────┐
│                                                       │
│  ┌─ PWA Bundle（我們的程式碼）─────────────┐            │
│  │  domain / adapters / shell             │            │
│  └───────┬─────────────────┬──────────────┘            │
│          │                 │                           │
│  ═══ TB1 ═══        ═══ TB2 ═══                        │
│          │                 │                           │
│  ┌───────▼──────┐   ┌──────▼───────┐                   │
│  │ localStorage │   │ Service Worker│                   │
│  │（使用者可改） │   │  Cache        │                   │
│  └──────────────┘   └───────────────┘                  │
└───────────────────────┬───────────────────────────────┘
                        │
                ═══════ TB3 ═══════   （網路）
                        │
        ┌───────────────┼────────────────┬──────────────┐
        ▼               ▼                ▼              ▼
   FX Providers    Analytics       Feature Flag    Maps Places
   （不可信回應）   （fire-forget）  （可用性依賴）  （不可信回應）
```

| 邊界 | 兩側 | 驗證要求 |
|---|---|---|
| **TB1** | 程式碼 ⇄ localStorage | 讀回**必須** schema validate（`c4-diagram` 已列） |
| **TB2** | 程式碼 ⇄ SW cache | 快取回應同樣需驗證，且需標示 age |
| **TB3** | 裝置 ⇄ 外部服務 | 所有回應驗 schema + 單位合理性（`error-handling` ST-FX-005） |

### 資產

| # | 資產 | 價值 | 機密性 | 完整性 | 可用性 |
|---|---|---|---|---|---|
| **A1** | **換匯建議的正確性** | **最高** | 低 | **最高** | 高 |
| **A2** | **燈號判定的正確性** | 高（含法規責任） | 低 | **最高** | 中（可降級隱藏） |
| **A3** | 使用者的行程與開支 | 中 | 中（僅存本機） | 中 | 中 |
| **A4** | 分析事件的真實性 | 中（KR 判定依據） | 低 | 高 | 低 |
| **A5** | FX API 金鑰（若採付費方案） | 中 | **高** | — | — |

> **A1／A2 的完整性是全表最高**，機密性反而最低。這是「無帳號產品」的典型輪廓——**沒有秘密可偷，但有數字可騙**。

## 3. STRIDE Analysis（per asset）

| # | 威脅 | STRIDE | 資產 | 情境 | 可能性 | 影響 | 風險 |
|---|---|---|---|---|---|---|---|
| **T1** | **上游 FX 回應單位錯誤**（per-1 vs per-100）導致燈號全錯 | **T**ampering | A2 | 供應商改格式或 fallback 到格式不同的來源 | 中 | **極高** | **高** |
| **T2** | **靜默 fallback**：以快取或模擬資料冒充即時 | **T** / **R**epudiation | A1、A2 | 實作為了「不要嚇到使用者」而隱藏來源 | 中 | 高 | **高** |
| **T3** | **無法還原當時算了什麼**（沒有留下計算依據） | **R**epudiation | A1 | 使用者投訴「你叫我換八萬結果不夠」，我們無法舉證 | 中 | 高 | **高** |
| **T4** | localStorage 被竄改後讀回造成錯誤顯示或 crash | **T** | A3 | 使用者或惡意擴充套件修改 | 低 | 中 | 中 |
| **T5** | 第三方腳本（分析／地圖）被入侵，注入程式碼 | **T** / **E**levation | A1、A3 | 供應鏈攻擊 | 低 | **極高** | 中 |
| **T6** | 分析事件被重複送出，KR1 虛高 | **T** | A4 | 連點、重試 | **高** | 中 | 中 |
| **T7** | FX 金鑰暴露在前端 bundle | **I**nfo Disclosure | A5 | 直接在 client 呼叫付費 API | 中 | 中 | 中 |
| **T8** | FX 供應商全數不可用 | **D**oS | A2 | 外部事故 | 中 | 中 | 中 |
| **T9** | 惡意大量呼叫耗盡 FX 額度 | **D**oS | A2 | 前端直呼且無節流 | 低 | 中 | 低 |
| **T10** | 行程內容含個資被送進分析 | **I** | A3 | 事件夾帶目的地以外的欄位 | 中 | 中 | 中 |

> **T1／T2／T3 是本模型的核心三角**：它們全都不是「駭客攻擊」，而是**我們自己會犯的錯**。
> 對一個以信任為唯一資產的產品，**最大的威脅來自內部實作的便宜行事**。

## 5. Mitigations（核心）

| 威脅 | 緩解 | 落點 | 狀態 |
|---|---|---|---|
| **T1** | ① 轉譯層強制正規化為「1 外幣 = N 台幣」<br>② **合理性檢查**：偏離歷史值 > 20% 即視為格式異常並切換來源<br>③ 每個 Provider 有固定樣本回應的轉譯測試 | `component-design` C3、`error-handling` ST-FX-005／R2 | 設計已定，**未實作** |
| **T2** | ① `FxResult.source` 為契約必填且必須誠實（C2）<br>② `north-star` C3 反指標監控模擬／快取曝光率<br>③ `unit-test` 強制「快取命中 → source=cache」案例<br>④ UI 的 `SourceBadge` 由 source 直接驅動，不可被覆寫 | `component-design` C2、`error-handling` R1 | 設計已定，**未實作** |
| **T3** | ① `CashSuggestion` 保留 `subtotal`／`buffered`／`rounded`／`itemCount` 四個中間值<br>② 行程存檔時一併存下當時的 `FxRate` 快照（含 provider 與 asOf）<br>③ 純函數可重算（`sequence-diagram` §6 冪等） | `class-diagram`、`data-model` | **部分未設計**：FxRate 快照是否入庫未定 |
| **T4** | 讀回一律 schema validate；失敗則隔離不刪除（ST-STO-003） | `error-handling` R3 | 設計已定 |
| **T5** | ① CSP 限制腳本來源<br>② 第三方腳本使用 SRI<br>③ 分析改用 beacon 端點而非完整 SDK | `non-functional-reqs` | **未處理** |
| **T6** | UI 送出中禁用按鈕；`generate` 綁渲染完成 | `frd` BR-05 D5、`sequence-diagram` T3 | **只有 UI 一層防線** |
| **T7** | 金鑰不進 client；若需付費 API，透過極薄的 serverless proxy | — | **與 `adr` ADR-001「無後端」衝突，未解** |
| **T8** | 三家 fallback + 快取降級 + 燈號可隱藏 | `component-design`、`runbook` 01 | 設計已定 |
| **T9** | 快取 TTL + CircuitBreaker | `component-design` | 部分緩解 |
| **T10** | 事件欄位白名單；只送國別／天數／幣別／來源類型 | `frd` BR-05 | 設計已定 |

### 明確接受的風險

| 風險 | 為什麼接受 |
|---|---|
| localStorage 明文儲存行程 | 資料僅存本機、無帳號、無高敏感內容；加密會增加複雜度卻不改變威脅模型（金鑰也在同一台裝置） |
| 使用者可自行竄改本機資料 | 竄改只影響自己；schema validate 已擋住 crash |
| 無防爬蟲／無 WAF | 靜態站，無可竊取的後端資料 |

## 10. Decision Log

| # | 決策 | 理由 | 影響 |
|---|---|---|---|
| D1 | **完整性優先於機密性** | 無帳號產品的資產是信任不是秘密 | 安全投資集中在 T1／T2／T3 |
| D2 | **T2 靜默 fallback 列為最高優先** | 它是我們自己會犯的錯，且會摧毀唯一資產 | 寫入 `code-review-checklist` 必查項 |
| D3 | **不加密 localStorage** | 同裝置金鑰無實質保護 | 記錄為明確接受的風險 |
| D4 | **T7 升級為架構問題** | 若選付費 FX，「無後端」的前提就不成立 | 需回 `adr` 開 ADR-002 |
| D5 | **合理性檢查（>20%）列為必做** | T1 的影響是 SEV-1 | 門檻需真實資料校準（見 TODO） |
