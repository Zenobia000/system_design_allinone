## 1. Executive Summary

這份路線圖刻意**不寫日期**，只寫「要解什麼問題、憑什麼往下走」。

理由很直接：PRD §10 把整個產品綁在一個 4 週驗證窗上，而**驗證窗的結果會決定 Next 存不存在**。在假設未驗證前排三季的功能日期，是把猜測包裝成計畫。

三段結構：

| 段 | 要解的問題 | 前提 |
|---|---|---|
| **Now** | 「我們的數字可信嗎、有人在用嗎？」 | 無 |
| **Next** | 「使用者願意留下來嗎？」 | Now 的 KR1 + KR2 達標 |
| **Later** | 「這能變成生意嗎？」 | Next 證實留存 |

## 2. Now / Next / Later

### Now（MVP 收尾 + 4 週驗證窗）

| 項目 | 要解的問題 | 對應需求 | 狀態 |
|---|---|---|---|
| **接入即時匯率** | 「省錢」主張目前是空話——燈號是模擬資料 | **P0-8** | ❌ 待補（阻擋項） |
| **基本使用分析** | 沒有它，驗證窗跑完也不知道結果 | **P0-9** | ❌ 待補（阻擋項） |
| 規劃輸入 → 三級距 → 建議換匯額 → 燈號 | 核心價值鏈 | P0-1～P0-5 | ✅ 已上線 |
| 儲存行程、開支紀錄、計畫 vs 實際 | 讓價值可被驗證（KR3） | P0-6、P0-7 | ✅ 已上線 |

> **Now 只有兩件事沒做完**（PRD 附錄自承）。任何在 P0-8／P0-9 之前插隊的提案，一律拒絕——它們是驗證窗的門票。

### Next（驗證通過後才存在）

| 項目 | 要解的問題 | 為什麼是現在 | 對應 |
|---|---|---|---|
| **帳號 + 雲端同步** | 「換手機資料就沒了」——免登入的代價 | 只有在證明有人要回來之後，跨裝置才值得付出複雜度 | PRD §10 V1、P2 |
| **確認所選（估算 → 真實紀錄）** | 建議值的準確度只能靠估算驗證，誤差來源說不清 | 直接改善 KR3（換匯準確度） | PRD §10 V1 |
| **分享／匯出（連結／PDF）** | 沒有分發管道（`competitive-scan` §5 弱點） | 口碑是唯一不花錢的取得手段 | PRD P1 |
| **即時匯率深化**（到價提醒） | 服務被 MVP 排除的「精算型」使用者 | `persona` Anti-Persona 老陳的需求 | PRD §10 V1 |

### Later（架構預留，先不做）

| 項目 | 要解的問題 | 前置條件 |
|---|---|---|
| 轉寄訂房信自動記帳 | 記帳摩擦太高（`user-research` F6） | 需先有帳號（Next） |
| 個人化推薦（「你都換太多」） | 建議值對個人不夠準 | 需累積個人歷史，資料量不足前無效（PRD §3 非目標） |
| 聯盟分潤 / 訂閱 | 產品要能養活自己 | **PRD §9 未決**：走分潤還是訂閱會反向影響產品排序 |
| 多人分帳 | 同行者拆帳 | 非核心假設，PRD §3 明列非目標 |

## 3. Outcomes（含 KPI）

路線圖的每一段用**成果**而非交付項判定是否可以往下走。

| 段 | Outcome（要證明什麼） | KPI | 門檻 | 未達的動作 |
|---|---|---|---|---|
| **Now** | 有人願意用，而且數字算得準 | 啟用率（`okr` KR1） | ≥ 40% | 依 `okr` 判定規則分流；可能重新檢視定位 |
| | | 30 天回訪（KR2） | ≥ 20% | 檢視 `journey-map` S8 缺口 |
| | | 換匯誤差 < 15% 比例（KR3） | ≥ 60% | **一票否決**：凍結新功能修算法 |
| | | 無提示差異化認知（KR4） | ≥ 60% | 定位失守 → 不是加功能能解決的 |
| **Next** | 使用者願意為了留下而付出成本（註冊） | 註冊轉換率 | 待定 `[L]` | 若低，代表跨裝置需求是我們腦補的 |
| | 建議值在真實紀錄下仍準 | KR3（真實紀錄版） | ≥ 60% | 算法需重做，不只是加緩衝 |
| **Later** | 有人願意付錢，或導流有價值 | 分潤點擊 → 成交率 | 待定 `[L]` | 回到 `competitive-scan` H1（市場太小）重評 |

### 明確不承諾的事

- **不承諾日期**。Next 的啟動時點取決於驗證窗結果，不取決於行事曆。
- **不承諾功能清單**。Next 的四個項目是**候選**，實際順序由驗證窗暴露的缺口決定。
- **不做 Later 的架構投資**，只保留不擋路的設計（例：`adr` 已要求 schema 預留 `userId`）。

## 10. Decision Log

| # | 決策 | 理由 | 影響 |
|---|---|---|---|
| D1 | **路線圖不標日期，改標前置條件** | 假設未驗證前的日期是猜的；對 stakeholder 也更誠實 | 週會不再花時間對日期，改對條件 |
| D2 | **Now 只保留 P0-8／P0-9** | PRD 附錄已收斂到這兩件 | 拒絕在驗證窗前加任何 P1 |
| D3 | **Next 整段以「Now 達標」為前提** | 避免團隊預先為 Next 做架構投資 | 節省 4 週窗內的工程注意力 |
| D4 | **商業模式（分潤 vs 訂閱）留在 Later 且不預選** | PRD §9 Open Question；預選會反向扭曲產品決策 | 驗證窗內不做任何變現埋點 |
| D5 | **P1 的「分享／匯出」升到 Next 首批** | 無分發管道是已知弱點，且成本低 | 與 `priority-matrix` 的 RICE 排序一致 |
