## 1. Executive Summary

**Spike-001：FX 資料源選型。**

這是 PRD §9 明列的**阻擋項**：P0-8 不能開工，`priority-matrix` 的 Effort 估不準，`component-design` 的 `fetchMA30` 契約可能根本無法實作。

Spike 要買回的不確定性只有一個：

> **有沒有一個免費或低成本的來源，同時提供「今日匯率」與「30 個交易日歷史」，涵蓋 JPY／KRW／THB？**

若答案是否，MA30 必須自行累積 → 上線後 30 個交易日內燈號不可用 → 直接打擊 G3 差異化認知。**這個後果比選錯供應商嚴重得多**，所以 spike 的重點是驗證歷史資料，不是比較誰的匯率準。

---

## 2. Spike Goal & Hypothesis

### 目標

| 項目 | 內容 |
|---|---|
| **要買回的不確定性** | FX 來源是否支援 MA30 所需的歷史序列；成本與額度是否落在驗證期可接受範圍 |
| **不在範圍** | 不做效能壓測、不做完整實作、不做 UI |
| **產出** | 一份可讀的比較表 + 一段能跑的最小驗證腳本 + ADR-002 的輸入 |

### 假設

| # | 假設 | 若成立 | 若推翻 |
|---|---|---|---|
| **H1** | 至少一個免費來源提供 30 日歷史 | 直接實作，Effort 維持 2.5 人週 | 需自建累積機制，Effort 至少翻倍 |
| **H2** | 免費額度足夠驗證期（估 1,200 次生成／週） | 驗證期零成本 | 需選付費方案或加強快取 |
| **H3** | 三家來源的匯率差異 < 0.5% | 可任意 fallback，使用者無感 | fallback 會造成數字跳動，需在 UI 標示來源 |
| **H4** | 涵蓋 JPY／KRW／THB | 主要市場滿足 | 部分幣別需第二來源 |

## 5. Candidate Options & Evaluation Criteria

### 候選

| # | 候選 | 類型 | 為什麼在名單上 |
|---|---|---|---|
| **A** | **Frankfurter**（ECB 資料） | 免費、開源、無金鑰 | `c4-diagram` 已列為第三順位；歷史資料 API 明確 |
| **B** | **台灣銀行公開匯率** | 免費 | 台灣使用者的心理錨點就是台銀牌告 |
| **C** | **Wise** | 商業 API | `c4-diagram` 列為第一順位；即時性最佳 |
| **D** | 自建累積（任一來源 + 每日快照） | 自製 | H1 推翻時的退路 |

### 評估準則（依權重）

| # | 準則 | 權重 | 為什麼是這個權重 |
|---|---|---|---|
| **E1** | **提供 ≥ 30 個交易日歷史** | **40%** | 這是 spike 的核心問題；無歷史則 P0-5 燈號從第一天就殘廢 |
| **E2** | 涵蓋 JPY／KRW／THB | 20% | 主要市場（種子簡報） |
| **E3** | 驗證期成本 | 15% | 種子簡報「4 週驗證窗、無商業模式」→ 月成本上限 $5 USD（`adr` 已用同一門檻） |
| **E4** | 額度與速率限制 | 10% | 對應 H2 |
| **E5** | 回應格式穩定性與文件品質 | 10% | 影響 `error-handling` ST-FX-005 的轉譯風險 |
| **E6** | 台灣使用者的心理可信度 | 5% | 台銀牌告的心理錨點效應（`user-research` F4 信任門檻） |

> **E1 給到 40% 是本 spike 最重要的判斷**。多數選型會把「即時性」或「準確度」放最高，但對 SmartTrip 而言，**燈號能不能存在**比**燈號準零點幾個 pip** 重要一個數量級。

### 驗證方式（每個候選都要跑）

```
1. 取今日 JPY/TWD、KRW/TWD、THB/TWD          → 驗 E2
2. 取過去 45 個自然日的序列，數出交易日筆數    → 驗 E1（必須 ≥ 30）
3. 檢查回傳單位（per 1 還是 per 100）          → 驗 E5、擋 runbook 04 陷阱
4. 連打 100 次記錄 429／延遲                   → 驗 E4
5. 三家同一時點的 JPY/TWD 互相比對             → 驗 H3
```

## 6. Time-box & Exit Criteria

| 項目 | 內容 |
|---|---|
| **Time-box** | **2 人日**（1 位 FE，2 天） |
| **超時處理** | 到點即停，**帶著不完整結果進 ADR 會議**，不延長 |
| **交付** | 比較表 + 驗證腳本 + 建議順序 + 未解風險 |

### 退出條件（滿足任一即結束）

| # | 條件 | 結論 |
|---|---|---|
| **X1** | 找到 ≥ 1 個來源滿足 E1 + E2 且成本 ≤ $5／月 | **成功退出**：H1 成立，進 ADR-002 拍板順序 |
| **X2** | 所有來源皆不滿足 E1 | **成功退出（結論為否）**：H1 推翻，啟動候選 D，並升級「上線後 30 交易日內燈號不可用」為產品決策 |
| **X3** | 2 人日用完 | **超時退出**：以已測部分做決策，未測項列入 ADR 風險 |

> **X2 也是成功**。Spike 的產出是知識不是程式碼——證明「做不到」與證明「做得到」等值。

### 明確不做的事

| 不做 | 為什麼 |
|---|---|
| 不寫正式的 Provider 實作 | Spike 的程式碼**預期被丟棄**；正式實作照 `component-design` 契約重寫 |
| 不比較匯率「準確度」 | 沒有真值可比；且 `user-research` F3 顯示使用者要的是決策許可不是小數點 |
| 不評估 V1 的到價提醒需求 | 屬 `roadmap` Later，現在評估會扭曲選型 |

## 10. Decision Log

| # | 決策 | 理由 | 影響 |

| D1 | **E1（歷史資料）權重拉到 40%** | 決定燈號能否存在，而非好不好 | 可能選出即時性較差但歷史完整的來源 |
