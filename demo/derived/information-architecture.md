## 1. Executive Summary

SmartTrip 的 IA 挑戰不是「內容太多找不到」，是**「只有一條路，但那條路上有一個必須被理解的數字」**。

因此本 IA 的設計目標與一般 App 相反：

- **不做導覽**。無漢堡選單、無底部 tab（MVP 階段），因為多一個入口就多一次分心。
- **單一主線 + 一個回訪入口**。主線是「輸入 → 三級距 → 建議換匯額」，回訪入口是「我的行程」。
- **深度優先於廣度**。建議換匯額底下必須能展開「怎麼算的」（`user-research` F4 信任門檻），這比多加一個頁面重要。

## 2. Top-level Categories

| # | 類別 | 內容 | 進入方式 | 為什麼是頂層 |
|---|---|---|---|---|
| **C1 · 規劃** | 輸入表單 → 三級距結果 → 時間軸 → 換匯建議 → 燈號 | 首頁預設 | 這是產品本體（`journey-map` S4） |
| **C2 · 我的行程** | 已存行程列表 → 單一行程詳情 → 開支紀錄 | 首頁次要入口 | 唯一的回訪理由（`okr` KR2） |
| **C3 · 關於／免責** | 算法說明、非投資建議聲明、隱私說明 | 頁尾 + 燈號旁的 inline 連結 | 種子簡報 §法規約束要求 |

> **刻意沒有的頂層**：設定、帳號、通知、探索／靈感。前三個因為免登入（無可設定之物），最後一個因為 `user-research` F5 已證明行程靈感不是我們的戰場。

## 3. Hierarchy Tree

```
/  (規劃 · C1)
├── 輸入表單
│     目的地 · 日期 · 消費幣別 · 預算範圍 · 心情/主題/同行/人數
│
├── 結果（同頁往下，不換頁）
│   ├── 三級距卡 × 3          Low / Mid / High
│   │     └── 展開 → 行程時間軸（每項：現金|刷卡 + 金額）
│   │
│   ├── 【建議換匯現金額】     ← 頁面的重心
│   │     ├── 外幣金額 + 台幣約當
│   │     └── 展開 →「怎麼算的」：cash 項目清單 + ×1.1 緩衝說明
│   │
│   └── FX 燈號（可獨立隱藏）
│         ├── 今日匯率 · MA30 · 偏離%
│         ├── 資料來源標籤（即時 / 快取 + 時戳 / 不可用）
│         └── 「非投資理財建議」免責
│
├── 我的行程 (C2)
│   └── /trip/{id}
│         ├── 行程詳情（同上結構，唯讀）
│         └── 開支紀錄
│               ├── 新增開支（現金 / 刷卡）
│               └── 計畫 vs 實際（超支 / 結餘）
│
└── 關於 (C3)
      ├── 換匯建議怎麼算的
      ├── 免責聲明
      └── 隱私與分析說明
```

### 層級規則

| 規則 | 內容 | 依據 |
|---|---|---|
| **最大深度 3** | 首頁 → 行程 → 開支。再深必須有強理由 | `persona` 小美「決策快怕麻煩」 |
| **結果不換頁** | 三級距與換匯建議在輸入的同一頁往下延伸 | `journey-map` MoT-1：3 分鐘內看到數字，換頁會增加中斷風險 |
| **「怎麼算的」就地展開** | 不跳頁、不開 modal | 信任說明離開現場就等於沒有 |
| **燈號可整塊消失** | 版面不得依賴燈號存在 | `frd` BR-02 降級規則；`feature-flag` `fx_signal_show` |

## 6. Taxonomy Rules

### 命名規則

| 概念 | 對外用詞 | 禁用 | 理由 |
|---|---|---|---|
| 建議換匯現金額 | **「建議換匯現金」** | 「兌換金額」「外幣預算」 | 使用者用「換多少」描述此事（`user-research` 引述） |
| 三級距 | **「省一點 / 剛剛好 / 玩滿一點」** | 「Low / Mid / High」 | 英文級距對主要 persona 無意義；`persona` 阿哲需要語意而非標籤 |
| 燈號 | **「換匯時機」** | 「買入訊號」「投資建議」 | 法規：不得暗示投資建議（種子簡報 §法規） |
| STRONG_BUY / BUY / HOLD | **「現在划算 / 還可以 / 再等等」** | 直接顯示英文常數 | 同上，且中文更貼近決策語言 |
| 開支紀錄 | **「花費對照」** | 「記帳」 | `user-research` F6：記帳一詞會勸退使用者 |

> 英文常數（`STRONG_BUY` 等）**僅存在於資料層與事件欄位**（`frd` BR-05），不得出現在 UI。

### 分類規則

| 規則 | 內容 |
|---|---|
| 行程項目只有兩種支付標籤：**現金 / 刷卡**。不做「兩者皆可」——模糊標籤會讓 `frd` BR-01 的 cash 總和失去意義 |
| 幣別分列不合併（`frd` BR-01 多幣別規則） |
| 「我的行程」以**出發日期**排序，不以建立時間——使用者找的是「下一趟」 |
| 過期行程（出發日已過）下沉但不刪除，因為開支對照要在旅途後才完成 |

## 10. Decision Log

| # | 決策 | 理由 | 影響 |
|---|---|---|---|
| D1 | **MVP 不做全域導覽（無 tab／漢堡）** | 只有一條主線，導覽只會分散注意力 | 若之後加功能需重審此決定 |
| D2 | **結果與輸入同頁** | 保護 MoT-1 的 3 分鐘 | `wireframe` 需處理長頁面的捲動與錨點 |
| D3 | **級距改用中文語意詞** | 英文標籤對主要 persona 無資訊量 | 影響 `high-fidelity-mockup` 與所有文案 |
| D4 | **「記帳」一詞全面禁用** | `user-research` F6 | 影響 P0-7 的所有 UI 文案 |
| D5 | **燈號區塊在版面上可整塊移除** | 降級與法規風險都可能導致隱藏 | 版面不得為燈號保留必要空間 |
