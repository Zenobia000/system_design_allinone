## 1. Executive Summary

一張表決定「測什麼、不測什麼、誰簽」。

SmartTrip 的測試策略被兩個現實條件夾住：

- **QA 只有 0.5 人力**（`stakeholder-map`）。任何需要大量手動回歸的策略都不可行。
- **4 週驗證窗**。測試投資必須集中在「出事會摧毀驗證」的地方，不是均勻覆蓋。

因此策略是**不對稱的**：

> **降級與資料正確性測到死，UI 細節與 P1 功能幾乎不測。**

理由：燈號算錯是 SEV-1（`runbook` 04），行程回顧的 UI 有瑕疵不影響任何 KR。

## 2. Scope

### 測

| # | 範圍 | 為什麼 |
|---|---|---|
| **S1** | 換匯計算（`frd` BR-01 全部規則含邊界） | `okr` KR3 的本體 |
| **S2** | 燈號判定與**降級路徑**（BR-02） | `threat-model` T1／T2；SEV-1 來源 |
| **S3** | 資料來源標示的端到端一致性 | `north-star` C3 反指標 |
| **S4** | 儲存／讀回，含 quota 與壞資料 | `runbook` 02；資料消失使用者不會回來 |
| **S5** | 分析事件的觸發時機與欄位白名單 | 事件錯 → KR1／KR2 判定錯 → 整個驗證窗白跑 |
| **S6** | 三級距不可退化、預算約束 | `frd` BR-03 |

### 不測（明確聲明）

| 不測 | 理由 | 風險接受者 |
|---|---|---|
| P1 功能（旅程回顧、心情故事、機票住宿估算） | 不影響任何 KR；PRD 附錄已定調為非核心 | PO |
| 跨瀏覽器矩陣（僅測 iOS Safari + Android Chrome 最新版） | `persona` 主要族群；`srs` §6.2 已限定 | PO |
| 視覺回歸 | 無專職設計、無基準圖；投資報酬低 | PO |
| 效能壓測 | 靜態站 + 無後端，瓶頸在外部 FX | DevOps |
| 多人分帳、帳號 | PRD §3 非目標 | — |
| **多幣別行程** | **不是不想測，是設計未定**（`wireframe`／`prototype` 未解） | **見 §12，這是缺口不是決定** |

## 3. Test Levels

| 層 | 誰寫 | 跑在哪 | 內容 | 通過門檻 |
|---|---|---|---|---|
| **L1 · 單元** | FE | PR gate | domain 純函數：BR-01 算式與邊界、BR-02 判定與門檻、BR-03 級距、開支彙總 | 全綠；**BR-01／BR-02 分支 100%** |
| **L2 · 整合** | FE | PR gate | 跨邊界契約與 12 條降級路徑（`integration-test` U1–U12） | 全綠；**U2／U3／U5／U9 為不可跳過項** |
| **L3 · 端到端煙霧** | FE + QA | 部署後 | 主線 6 步（`prototype` F1–F6）在真實部署上跑一次 | 全綠才進 canary 下一階段 |
| **L4 · 探索式測試** | QA | 手動，每次發布前 | 時間盒 60 分鐘，針對本次變更的模組自由探索 | 無 S1／S2 級缺陷 |
| **L5 · UAT** | PO + QA | 預發布 | 見 `uat` 卡 | 見該卡簽核條件 |

> **沒有 L1 覆蓋率百分比目標**，只有**指定模組的分支覆蓋要求**。整體覆蓋率是虛榮指標——把 UI 元件測到 80% 不會讓燈號更準。

## 9. Risks（top 3）

| # | 風險 | 影響 | 緩解 |
|---|---|---|---|
| **R1** | **AC 未寫完就開始測**，測試變成「描述現況」而非「驗證需求」 | 錯誤行為被測試固化，永遠改不掉 | P0-8／P0-9 的 AC 必須先於實作完成；QA 參與 `user-story` 拆解 |
| **R2** | **QA 0.5 人力撐不起 L4 + L5** | 探索式測試與 UAT 被壓縮成走過場 | L4 嚴格時間盒；L5 由 PO 主導、QA 支援 |
| **R3** | **降級路徑測試在 CI 變慢後被跳過** | `threat-model` T2 失去防線 | U2／U3／U5／U9 標為不可 skip；CI 設定禁止 `.skip` 進主線 |
