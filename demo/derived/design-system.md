## 1. Executive Summary

**先講一個反對意見**：一個 4 週驗證窗、FE 2 人、單一主線的 MVP，通常**不需要設計系統**。做一套完整 token + 元件庫是典型的過度投資。

本文件因此刻意縮到最小，只定義**三件不定會出事**的東西：

1. **金額的排版規則**——產品的重心是一個數字，數字排版不一致會直接傷害可信度。
2. **狀態色的語意**——燈號有法規風險，顏色不能暗示投資建議的強弱。
3. **無障礙底線**——一次做對比事後補便宜。

其餘（陰影層級、圓角比例、動效曲線）**明確不定義**，交給實作者判斷。

## 2. Design Tokens

### 色彩

| Token | 值 | 用途 | 約束 |
|---|---|---|---|
| `--ink` | `#1a1a1a` | 主要文字 | — |
| `--ink-mute` | `#6b6b6b` | 次要說明、時戳 | 對白底 ≥ 4.5:1 |
| `--paper` | `#ffffff` | 底色 | — |
| `--surface` | `#f5f3ef` | 卡片、展開區 | — |
| `--accent` | `#1f6f5c` | 主 CTA、建議換匯金額 | 綠 = 錢，但**不用鮮綠**（避免股市聯想） |
| `--signal-good` | `#2e7d5b` | 「現在划算」 | 見下方語意約束 |
| `--signal-mid` | `#8a7a3f` | 「還可以」 | |
| `--signal-hold` | `#6b6b6b` | 「再等等」 | **灰色，不是紅色** |
| `--warn` | `#a35a2a` | 快取／模擬資料標籤 | |
| `--error` | `#9b2c2c` | 表單錯誤、儲存失敗 | |

> **狀態色的語意約束（法規相關）**：
> - 燈號**不得使用紅／綠對立配色**。紅綠是金融漲跌的既有語彙，會強化「投資建議」的暗示，牴觸種子簡報 §法規約束。
> - 「再等等」用**中性灰**，不用紅色——紅色暗示「不要買」，那是建議；灰色只表達「無特別訊號」。

### 字級

| Token | 值 | 用途 |
|---|---|---|
| `--fs-hero` | 40 / 44 | **建議換匯金額**（唯一使用者） |
| `--fs-title` | 22 / 30 | 區塊標題 |
| `--fs-body` | 16 / 26 | 內文（不低於 16，避免 iOS 自動縮放） |
| `--fs-small` | 13 / 20 | 時戳、免責、說明 |
| `--fs-mono` | 15 / 24 | 金額明細（等寬，見下） |

### 數字排版（本系統最重要的一組規則）

| 規則 | 內容 | 理由 |
|---|---|---|
| **等寬數字** | 所有金額使用 `font-variant-numeric: tabular-nums` | 明細逐列對齊；不對齊的數字看起來像算錯 |
| **千分位** | 一律加 | `¥82000` 與 `¥82,000` 的可讀性差距極大 |
| **幣別符號在前，代碼在後** | `¥ 82,000` / `NT$ 17,400` | 與台灣使用者習慣一致 |
| **台幣約當永遠成對出現** | 外幣金額下方必附台幣 | `persona` 小美對日幣無量級感 |
| **不做金額動畫** | 數字不做跑分效果 | 跑分會讓人以為還在計算，傷害 MoT-1 的確定感 |

### 間距

`--space-1: 4px` → `2: 8` → `3: 12` → `4: 16` → `5: 24` → `6: 32` → `7: 48`（4 的倍數，不再細分）

## 3. Core Components

只定義 7 個，全部來自 `wireframe` 已出現的元素。

| # | 元件 | 用途 | 關鍵狀態 | 備註 |
|---|---|---|---|---|
| **C1 · AmountHero** | 建議換匯金額 | 正常 / 無現金需求 / 載入中 | 產品重心；含台幣約當與「已含 10% 緩衝」 |
| **C2 · DisclosurePanel** | 「怎麼算的」展開 | 收合 / 展開 | `wireframe` W4；**不得改成 modal** |
| **C3 · SignalBlock** | 換匯時機 | 三種燈號 / 快取 / **整塊不存在** | 「不存在」是正式狀態，非錯誤 |
| **C4 · SourceBadge** | 資料來源標籤 | 即時 / 快取+時戳 / 模擬 | `north-star` C3 依賴它 |
| **C5 · TierCard** | 級距卡 | 預設 / 展開 / 三張同值（`frd` BR-03） | 中文級距名 |
| **C6 · PayTag** | 現金／刷卡標籤 | 兩種，無第三種 | 模糊標籤會破壞 BR-01 |
| **C7 · BudgetBar** | 計畫 vs 實際 | 結餘 / 超支 | 超支不用紅色警示，用中性提示（不責備使用者） |

### 明確不做的元件

Modal、Toast、Tab、Carousel、Skeleton 動畫、空狀態插圖。理由：主線用不到，做了就要維護。

## 6. A11y Baseline

| # | 要求 | 標準 | 為什麼是底線 |
|---|---|---|---|
| **A1** | 文字對比 | 內文 ≥ 4.5:1，大字 ≥ 3:1 | 主要族群 25–40 歲但常在**戶外／車上**使用 |
| **A2** | **燈號不可僅靠顏色傳達** | 顏色 + 文字 + 圖形 | 色覺障礙者；**且法規上文字才是正式表述** |
| **A3** | 觸控目標 | ≥ 44×44px | 行動單手操作 |
| **A4** | 字級不鎖死 | 支援系統字級放大至 200% 不破版 | |
| **A5** | 表單標籤 | 每個輸入有可見 label，錯誤訊息與欄位以 `aria-describedby` 關聯 | `wireframe` §12 的收合欄位驗證問題 |
| **A6** | 焦點可見 | 鍵盤操作有明顯 focus ring | |
| **A7** | 金額語意 | 螢幕閱讀器須讀出「日圓 八萬二千」而非逐字 | 金額是產品核心資訊 |

## 10. Decision Log

| # | 決策 | 理由 | 影響 |
|---|---|---|---|
| D1 | **設計系統範圍縮到最小** | 4 週窗 + FE 2 人，完整系統是過度投資 | 只定會出事的部分，其餘授權實作者判斷 |
| D2 | **燈號禁用紅綠對立配色** | 避免金融漲跌暗示，牴觸法規約束 | 與多數金融 App 慣例不同，需在 `usability-test` 確認可理解 |
| D3 | **「再等等」用灰色不用紅色** | 紅色等於給出「不要換」的建議 | 同上 |
| D4 | **金額使用等寬數字且不做動畫** | 對齊 = 可信；動畫 = 還在算 | 影響 C1／C2 實作 |
| D5 | **超支不用錯誤色** | 超支是使用者的事實不是系統錯誤 | C7 的視覺處理 |
| D6 | **不建元件庫套件**，token 以 CSS 變數落地 | 兩人專案不需要跨專案共享 | 若 V1 擴編需重審 |
